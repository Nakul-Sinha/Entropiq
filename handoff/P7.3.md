# Handoff P7.3: GitHub Action for pull requests
- Status: done (release-model.yml left out on purpose, see deviations)
- Branch / PR: step/P7.3-github-action-for-pull-requests, https://github.com/Nakul-Sinha/Entropiq/pull/35

## What was built

A composite action in `action/` that any workflow can use as `Nakul-Sinha/Entropiq/action@<ref>` (or
`./action` inside this repository). It installs the CLI from its own copy of the repository, fetches the
released production model, runs `tdp diff . --base=BASE --format json` (and `tdp report . --format sarif`
when asked), keeps exactly one pull request comment up to date, writes the job summary and applies
`fail-on`. Usage, inputs, outputs, an example workflow and the release commands are in `action/README.md`.

Steps of `action/action.yml`, in order: fail fast on Windows; `astral-sh/setup-uv@v7` (cache off); `uv sync
--frozen --no-dev --no-editable --package tdp-cli --python 3.12` from `github.action_path/..` into
`$RUNNER_TEMP/entropiq/venv`; `run.py resolve`; `actions/cache/restore@v5` (key `tdp-model-<version>`);
`run.py fetch`; `actions/cache/save@v5` only after a fresh verified download; the analysis; the SARIF upload
(`github/codeql-action/upload-sarif@v4`, `continue-on-error: true`); `run.py report` last, so the fail-on exit
code comes after the comment and the upload. No `run:` string contains an expression: every value reaches
bash through `env`.

## Deviations from the plan and why

- The CLI is installed with `uv sync --frozen --package tdp-cli` from the action's own checkout, not `pip
  install git+https://...@action_ref#subdirectory=cli`: the repository is private (a pip clone needs
  credentials), `tdp-core` is not on PyPI, and `github.action_ref` is empty for `uses: ./action`. It is still
  the CLI at the action ref, with the locked versions CI uses.
- uv replaces setup-python and pip; `--python 3.12` keeps `UV_PYTHON` out of the caller's job.
- No `release-model.yml`: bundles are built and promoted on the laptop and never exist in CI. The manual `gh
  release create` commands are in `action/README.md` (the orchestrator allowed this).
- Extra `github-token` input (composite actions cannot read secrets) and extra outputs for the self-test.
- The comment is rendered in `run.py` from the diff JSON instead of posting `tdp diff --format md`, to get
  separate band and priority columns and a one-line summary; escaping reuses `tdp_core.report.markdown`.
- A marker comment counts as the action's own only when its author is a bot or the token's user, so a human
  comment that quotes the marker is never edited.
- `fail-on` is not applied when the demo model scored the files (a warning says so).
- The SARIF upload cannot succeed on this private repository without GitHub code security; it is
  `continue-on-error`, so the acceptance line "SARIF upload succeeds" is met only on repositories with code
  scanning. The self-test checks that the SARIF file is written.
- Helpers live in the test file (no `conftest.py` helpers), because `--import-mode=importlib` cannot import
  from a conftest.

## How to verify (commands)

```bash
uv run pytest cli/tests/action -q
uv run pytest -q
uv run ruff check . && uv run ruff format --check . && uv run mypy packages/core
uv run mypy action/run.py
gh release view model-ranker-2026.10.1 --repo Nakul-Sinha/Entropiq
gh pr checks 35 --repo Nakul-Sinha/Entropiq
gh api "repos/Nakul-Sinha/Entropiq/issues/35/comments" --paginate \
  --jq '[.[] | select((.body // "") | startswith("<!-- tdp-report -->"))] | length'   # prints 1
```

Local smoke run of the three subcommands against the real release (base `HEAD~3`, `fail-on: high`): resolve
and fetch gave `source=release` with the sha256 verified; `tdp diff --model-dir` took 20 s (analysis 11 s);
`report` exited 1 with "Fail-on high: 3 changed files are High or Critical, so this check fails."; `tdp
report --format sarif` reused the analysis and wrote 39 results.

## Known issues / limitations

- Linux and macOS runners only.
- Repositories other than this one need Actions access to this private repository and a token that can read
  its releases; otherwise they get the demo model (stated in the comment).
- SARIF covers the whole repository at High and above, not only the changed files; code scanning shows which
  alerts are new.
