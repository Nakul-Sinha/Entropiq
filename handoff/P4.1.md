- Deviations from the plan and why:
  - Knapsack weights round **up** (`max(1, ceil(cost / step))`) and the budget rounds **down**
    (`floor(budget / step)`), instead of `round()`. With `round()` the plan's own constraint breaks: two 0.6 h
    files fit a 1 h budget at a 0.5 h step (1.2 h chosen), and on 5,000 random items a 200 h budget chose 208 h.
    With ceil the true hours of the chosen files never exceed the budget beyond float rounding. Both conversions
    use a 1e-9 unit tolerance so float noise (`40 / 0.05`, `0.3 / 0.1`) never gains or loses a unit.
  - Default `step` is 0.05 h (3 minutes) instead of 0.5 h. Ceil at 0.5 h wastes up to half an hour per chosen file:
    on click, flask and celery a 40 h plan used only 36.7 to 38.1 h. At 0.05 h it uses 39.4 to 39.7 h with 3 to 5%
    more benefit, the waste is under 3 minutes per file, and 5,000 items with a 200 h budget are still solved
    exactly in about 0.06 s.
  - Exact search details: items with zero benefit, and items larger than the whole budget, are dropped first; if
    everything left fits, all of it is returned (optimal since benefits are >= 0). The DP is vectorised with
    numpy (one pass per item over all capacities, equivalent to the downward capacity loop). Ties: items are
    processed in path order and an item is taken only on a strict improvement, so ties go to the paths that sort
    first and the output does not depend on the input order.
  - Greedy fallback: used when `items * (capacity + 1) > MAX_DP_CELLS` (counted after filtering) and also when
    the capacity exceeds `MAX_DP_CAPACITY` (1,000,000 units, 50,000 h at the default step). The second guard is new:
    it keeps the DP's float arrays under 8 MB even for absurd budgets with only a few items. Greedy order is
    benefit per unit (then path), an item that does not fit is skipped and the scan continues, and the best single
    item (by benefit, then path) replaces the greedy set only when it is strictly worth more. This keeps at least
    half of the optimum (tested).
  - Public functions (the plan says "name without a leading `_` in its last segment"): additionally, names are
    counted once (property getter and setter, `@overload` stubs), the last segment must be an identifier (drops
    the parser's `<unknown>` fallback), and functions nested inside another function (`outer.inner`,
    `factory.Impl.run`) are excluded because a closure cannot be tested directly. Methods of nested classes
    (`A.B.method`) still count.
  - `breakdown` always has the five `COST_KINDS` keys (zeros included) and holds raw minutes per kind, before the
    blast radius multiplier and the `min_hours` floor. The key is `tests` (as P0.2's serialize test already uses).
  - A cost model is any mapping merged over the package defaults: missing keys keep the default, unknown keys are
    ignored (`load_cost_model` logs one warning for them), and a known value must be a finite number >= 0
    (strings, booleans, NaN and negatives raise `ValueError`).
  - Input validation: `estimate_cost` raises `KeyError` for a missing row column and `ValueError` for a NaN,
    infinite or negative value; `benefit` requires `0 <= risk <= 1` and finite dependents >= 0; `knapsack` and
    `schedule` reject repeated paths and non-finite numbers; `make_plan` rejects a bad budget, repeated score
    paths, a non-unique feature index and non-finite candidate hours.
  - Kept literal from the plan: complexity sums over functions only (module-level code is not costed);
    duplication uses `clone_groups` as P1.3 defines it; `min_priority` defaults to settings (50).
  - Schedule details the plan leaves open: only direct import edges between chosen files count; self loops are
    ignored and chosen files missing from the graph are isolated; members of a cycle group are ordered by roi
    descending, then path; groups are numbered 1..k in fix order; the heap key is `(-max member roi, smallest
    member path)`, which is unique, so networkx's internal ids never decide the order. The cycle reason names the
    other members in plan order in plain English (`a.py`, `a.py and b.py`, `a.py, b.py and c.py`, then
    `a.py, b.py, c.py and 2 more`). Rule order: cycle, then dependent (the importer that comes first in the
    plan), then best roi.
  - `make_plan` accepts either feature frame shape: indexed by path (`AnalysisResult.features`) or with a `path`
    column (`BuildResult.features`). Candidates need `hours > 0`; a score whose path has no cost entry is skipped.
    Each `PlanStep.cost` is the same object as `costs[path]`.
  - Added public helpers beyond the plan's interface: `load_cost_model`, `public_function_names`, `cost_units`,
    `capacity_units`, `import_graph_from_edges` (the last for P5.4, which rebuilds plans from the stored graph).

- Known issues / limitations:
  - `clone_groups` is about 0.2 to 0.3 per duplicated line on these repositories because P1.3 counts distinct
    shared fingerprints, not clone regions, so `duplication_per_group` (30 minutes) dominates the estimate (30 to
    51% of raw minutes). Consider lowering it when the cost model is tuned; bundles carry their own copy.
  - Module-level complexity (`module_cc`) is not costed, as the plan says.
  - The schedule only sees direct import edges between chosen files; a dependency that passes through a file
    outside the plan does not order the two files.
  - Rounding costs up wastes under 3 minutes per chosen file, so a plan can leave a little budget unused.
  - `total_hours <= budget_hours` holds up to float rounding: the 1e-9 unit tolerance can admit at most about
    5e-11 h per chosen file (for example three 0.1 h files fit a 0.3 h budget at a 0.1 h step although their float
    sum is 0.30000000000000004). Tests check `<= budget + 1e-9`.
  - Inputs over `MAX_DP_CELLS` or `MAX_DP_CAPACITY` use the greedy fallback (at least half of the optimum, usually
    much closer). At the default step that takes, for example, more than 1,250 candidates that do not all fit a
    2,000 h budget, or a budget over 50,000 h. The boolean DP table can reach 50 MB at the limit.
  - Reasons are English sentences only.
