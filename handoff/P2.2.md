    `graph_features`); columns exactly `COCHANGE_FEATURE_COLUMNS` with dtypes int64, float64, int64, float64.
    Every ranked path gets a row (zeros without history). No ranked paths gives an empty frame with the same
    columns, dtypes and index name.
  - Edges: every strong directed pair among the ranked files, sorted by `(a, b)`, as plain Python
    `str, str, int, float`. Both directions appear when both are strong (their confidences differ when the
    files have different commit counts). Entries with source `a` = `cochange_partners[a]`.

- Rules as implemented (module docstring has the full text):
  - History: commits with `is_bulk == False` and `author_time <= snapshot.time` (inclusive, whole seconds,
    `snapshot.time` floored), or with `reachable` given, `is_bulk == False` and `sha in reachable`.
  - Touch: a commit touches a ranked file when any of its `file_changes` rows has `path` or `old_path` among the
    file's names (`lineage.get(p, frozenset()) | {p}`); once per commit and file. Same rule as P2.1.
  - `M` is a binary SciPy `csr_array` (history commits that touch a ranked file x ranked files), `S = M.T @ M`,
    `support(a, b) = S[a, b]`, `conf(a -> b) = S[a, b] / S[a, a]` (compared directly with the threshold, so
    7/10 reaches 0.7). Candidate: other ranked file, `support >= cochange_min_support`, no shared name.
    Strong partner: candidate with `conf >= cochange_min_confidence`.
- Deviations from the plan and why:
  1. **`reachable` keyword (section 15.5)** on both functions, keyword-only, default None. When given it replaces
     `author_time <= T` (the snapshot time is then not read at all); the bulk filter still applies, shas that are
     not in `hist.commits` are ignored, and an empty set gives all zeros.
  2. **Universe = ranked files.** Matrix columns and partners are only the non-test members of `paths`, not
     every file alive at T. P5.2 draws edges between ranked files, and files such as `CHANGES.rst` or
     `setup.cfg` would otherwise become partners of nearly everything (and always "hidden", since they are not
     import graph nodes). Test files in `paths` get no row and are never partners.
  3. **Lineage overlap.** Two ranked files whose name sets intersect are never candidates of each other (not
     partners, not in `cochange_max_conf`, no edge). P1.1's lineage is name based: when a file is renamed and a
     new file reuses the old name, every commit to that name counts for both, so the pair looks perfectly
     coupled through commits that edited only one of them. Measured at the latest snapshot: flask has 4 such
     directed pairs (`src/flask/app.py` and `blueprints.py` were split into `src/flask/sansio/`), celery 2,
     pylint 2. Each file's own commit count keeps the shared commits (same as P2.1's `commits_total`).
  4. **`test_cochange_rate`** applies `is_test` to the historical names (`path` and `old_path`) in the commit's
     rows, so deleted and renamed tests count, and excludes the file's own lineage names: "also touches a test
     file" means another file. This matters for celery, where 16 ranked files have test-named history (helpers
     that used to live under `celery/tests/`). Bulk commits are excluded; no commits gives 0.0.
  5. **`cochange_max_conf`** is the maximum confidence over candidates (support >= min support) regardless of
     the confidence threshold, 0.0 without candidates (the plan's "partners with support >= min support"), so it
     can be below `cochange_min_confidence` while `cochange_partners` is 0.
  6. **`cochange_edges` ignores `import_graph`.** It takes the same arguments as `cochange_features` ("same
     args") and returns all strong pairs with or without an import edge; the hidden-coupling filter is the
     caller's job (P5.2).
  7. **ValueError** for `cochange_min_support < 1`, `cochange_min_confidence` outside 0..1 (NaN included), and a
     naive `snapshot.time` when `reachable` is None (checked even when there are no ranked files).
  8. **Index and dtypes mirror P1.4** (`str` index named `path`, int64/float64 columns); P2.7 casts to float32.
  9. Branch name `step/P2.2-co-change-coupling-features` (given by the orchestrator) instead of
     `step/P2.2-cochange`.

- Known issues / limitations:
  - Lineage is name based (P1.1), so a reused name still merges two files' histories for their own counts;
    only the pair itself is protected (deviation 3).
  - Test detection is whatever `is_test` says. P1.2's `is_test_file` does not treat a `t/` directory as tests:
    celery keeps its tests in `t/unit/...`, so those files are ranked as source files and can be partners.
  - A commit touching a test file through a name that is also in another ranked file's lineage still counts as
    a test touch for the other files (historical names decide).
  - Co-change between a ranked file and non-Python files is not measured (deviation 2).
