- Public API added (exact signatures, module paths):
  - `tdp_ml.baselines`
    - `BASELINES = ("random", "loc", "complexity", "hotspot", "prior_bugs", "rf", "xgb_point")` (report order)
    - `N_SHUFFLES = 100`, `DEFAULT_JOBS = 4`, `RF_PARAMS`, `XGB_POINT_PARAMS`
    - `FloatArray = npt.NDArray[np.float64]`
    - `loc_scores(test) -> FloatArray` (`sloc`), `complexity_scores(test) -> FloatArray` (`cc_sum`),
      `hotspot_scores(test) -> FloatArray` (`pct_churn_decayed * pct_cc_sum`),
      `prior_bugs_scores(test) -> FloatArray` (dense lexicographic rank of
      `(prior_latent_bugs, prior_bugfix_commits)`)
    - `rf_fit_predict(train, test, *, n_jobs: int = 4, seed: int = 42) -> FloatArray` (positive-class
      probability of `RandomForestClassifier(n_estimators=500, min_samples_leaf=5,
      class_weight="balanced_subsample")` on `has_latent_defect`)
    - `xgb_point_fit_predict(train, test, *, n_jobs: int = 4, seed: int = 42) -> FloatArray` (predicted pain of
      `XGBRegressor(n_estimators=500, learning_rate=0.05, tree_method="hist")`)
    - `baseline_fit_predict(name: str, *, n_jobs: int = 4, seed: int = 42) -> FitPredict` (every baseline except
      `random`)
    - `run_random(df, protocol: str, *, n_shuffles: int = 100, seed: int = 42, horizon_days: int = 365) -> pd.DataFrame`
    - `run_baseline(df, name: str, protocol: str, *, n_jobs=4, seed=42, horizon_days=365, n_shuffles=100) -> pd.DataFrame`
    - `run_baselines(df, protocol: str, names: Sequence[str] = BASELINES, *, n_jobs=4, seed=42, horizon_days=365,
      n_shuffles=100) -> pd.DataFrame`
    - `check_baselines(names: Sequence[str]) -> list[str]`, `order_per_query(per_query) -> pd.DataFrame`
  - `tdp_ml.commands.baselines`: `tdp-ml baselines`, plus
    - `summary_paths(root) -> tuple[Path, Path]`
    - `write_summary(root, *, n_boot=1000, seed=42, provenance: Mapping[str, Any] | None = None) -> str | None`
      (with `provenance`, protocol files whose note does not match are left out with a warning)
    - `PROVENANCE_KEYS = ("dataset_sha256", "horizon_days", "seed", "shuffles")` (the fields that must match)
    - `file_sha256(path) -> str`, `provenance_path(root, protocol) -> Path` (`<root>/baselines_<protocol>.json`)
    - `dataset_provenance(path, df, *, horizon_days, seed, shuffles, jobs) -> dict[str, Any]` (fields
      `dataset`, `dataset_sha256`, `rows`, `queries`, `repos`, `horizon_days`, `seed`, `shuffles`, `jobs`)
    - `read_provenance(path) -> dict[str, Any] | None` (None when missing, unreadable or not an object),
      `write_provenance(path, provenance) -> Path` (atomic), `same_provenance(stored, current) -> bool`
  - Command: `tdp-ml baselines [--protocol temporal|lopo|all] [--model NAME]... [--dataset PATH] [--out-dir PATH]
    [--jobs N] [--shuffles 100] [--n-boot 1000] [--horizon-days 365] [--seed 42] [--force]`.
    Writes `<results>/baselines_<protocol>.parquet` (per-query, P3.1 format, one `(model, protocol)` run per
    baseline), `<results>/baselines_summary.parquet` (the `summarize` frame for every protocol file present)
    `<results>/baselines_<protocol>.json` (provenance note: dataset sha256 and options) and
    `<results>/baselines_summary.md` (each protocol's provenance, then ranking metrics with 95%
    repository-bootstrap intervals), and prints the table. Baselines already in a protocol's file are skipped
    unless `--force`, but only when its note matches; a rerun of some baselines replaces only their rows.

- Deviations from the plan and why:
  1. The command is a plug-in module `ml/tdp_ml/commands/baselines.py` (section 15.4) instead of an edit to
     `cli.py`.
  2. `rf` and `xgb_point` take their thread count from `--jobs` (default 4, the laptop limit of 15.3) instead
     of a hard-coded `n_jobs=-1`; `--jobs -1` restores every core. Results do not depend on the thread count.
  3. `random` draws shuffle `i` from `numpy.random.default_rng([seed, i])` and stores, per query, the mean of
     each metric over the shuffles (the expected value of a random order). Its `split` and query columns
     equal those of every other baseline, so paired tests on `qid` work.
  4. `prior_bugs` scores are the dense rank of the `(prior_latent_bugs, prior_bugfix_commits)` pair, which is
     an exact lexicographic tie break; files equal on both keys tie and the evaluator breaks them by path.
  5. `rf` returns a constant score (the only label) when a training set has a single class, with a warning,
     instead of failing; this never happens on the real dataset.
  6. Only ranking metrics are reported: the `rf` probabilities come from a class-balanced forest and are not
     meant to be calibrated, so probability metrics would mislead.
  7. Stored rows are reused only when the protocol's JSON note matches the current run on the dataset
     sha256, `--horizon-days`, `--seed` and `--shuffles` (not `--jobs`, which does not change results).
     Otherwise the command says so, drops every stale row and reruns every requested baseline, even with
     `--force` or a subset of `--model`. The summary leaves out protocol files whose note does not match
     and lists each included protocol's provenance, so a rebuilt dataset can never leave stale numbers.

- Known issues / limitations:
  - The learned pointwise baselines do not beat the hotspot heuristic on NDCG@10 with 20 test queries; the
    intervals overlap heavily, so the ranker in the next step should be judged with the paired tests, not
    by eye.
  - The dataset pipeline is merged and these numbers come from its dataset (sha256 above). A rebuilt
    dataset has a different sha256, so the next `tdp-ml baselines` run detects it and reruns everything.
  - The LOPO random baseline is the slowest heuristic (100 shuffles times 20 splits, about 40 s on 16 cores,
    a few minutes on the laptop); `--shuffles` lowers it for quick checks.
