# Handoff P7.1: Command-line interface (interactive Entropiq app plus `tdp analyze`)
- Status: done
- Branch / PR: step/P7.1-command-line-interface, https://github.com/Nakul-Sinha/Entropiq/pull/29

## What was built

`cli/tdp_cli` (package `tdp-cli`) is a full interactive terminal app in the style of Claude Code, plus the
non-interactive Typer commands the GitHub Action needs. Console scripts `entropiq` and `tdp` both run
`tdp_cli.main:main`; `python -m tdp_cli` works too. With no subcommand the shell opens: gradient ENTROPIQ logo
(figlet ANSI Shadow, violet #8B5CF6 to cyan #06B6D4, ASCII letters when the terminal cannot encode block
characters, one word below 61 columns), tagline, version line (`entropiq 0.1.0 · model <version> · production
model | demo model | custom model`), a Welcome panel with three tips, the yellow demo notice when a demo model is
in use, then a prompt_toolkit input line (`entropiq ❯`), slash-command completion with descriptions, argument
completion, history in `<home>/history`, auto-suggest, and a bottom toolbar (key hints, loaded repository, demo
marker). Typing `/` lists every command, unknown input suggests the closest command, Ctrl+C cancels the running
command (or clears the line), Ctrl+D or `/quit` exits. When stdin is not a terminal (pipes, CI, mintty) the shell
reads plain lines instead and echoes each one.

Commands shipped: `/analyze` (`/analyse`), `/history`, `/open` (`/load`), `/status`, `/model`, `/settings`,
`/help` (`/h`), `/clear` (`/cls`), `/quit` (`/exit`, `/q`). Typer subcommands: `analyze`, `history`, `model`, plus
root options `--version/-V`, `--model-dir`, `--dev-model`.

## Public API added (exact signatures, module paths)

Everything is importable from the module named; `tdp_cli/__init__.py` only holds `__version__ = "0.1.0"`.

`tdp_cli.errors`
- `class CliError(Exception)`: `__init__(self, message: str, *, exit_code: int = 1, hint: str | None = None)`; attributes `message`, `exit_code`, `hint`.
- `class UsageError(CliError)`: same signature, default `exit_code=2`.
- `class ShellExit(Exception)`: raised by `/quit`.

`tdp_cli.args`
- `split_args(text: str) -> list[str]` (shlex posix, backslashes literal so Windows paths survive, no comments; `UsageError("unbalanced quotes")`).
- `split_args_lenient(text: str) -> list[str]` (never raises, closes a dangling quote).
- `quote_arg(text: str) -> str` (double quotes when the text has whitespace or is empty).
- `@dataclass(frozen=True, slots=True) class ParsedArgs: positionals: tuple[str, ...]; options: dict[str, str | bool]` with `flag(name) -> bool` and `value(name) -> str | None` (`"--ref"` or `"ref"`).
- `parse_args(args: Sequence[str], *, values: Collection[str] = (), flags: Collection[str] = (), max_positionals: int | None = None) -> ParsedArgs`: `--ref v1`, `--ref=v1`, `--` ends options, any other word starting with `-` is an option; `UsageError` for an unknown option (lists the valid ones), a missing value, a value on a flag, or too many positionals.

`tdp_cli.registry`
- `GROUP_ORDER: Final = ("Analysis", "Explore", "Plan", "Report", "Session", "General")`; unknown groups sort after "Report" alphabetically; "Session" then "General" are always last. `group_rank(group) -> tuple[int, str]`.
- `NAME_PATTERN = ^[a-z][a-z0-9-]{0,31}$` (names, aliases and CLI names).
- `@dataclass(frozen=True, slots=True) class Suggestion: text: str; meta: str = ""`
- `type Handler = Callable[[Session, Sequence[str]], None]` (args = words after the command name, already split)
- `type ArgCompleter = Callable[[Session, Sequence[str], str], Iterable[Suggestion]]` (session, finished args, word being typed)
- `@dataclass(frozen=True, slots=True) class Command: name: str; help: str; handler: Handler; group: str = "General"; aliases: tuple[str, ...] = (); usage: str = ""; details: str = ""; complete: ArgCompleter | None = None; needs_analysis: bool = False; cli: Callable[..., Any] | None = None; cli_name: str | None = None`, property `usage_line` (usage or `/<name>`).
- `class CommandRegistry`: `add(command)`, `add_cli(name, function, *, help, group="General")`, `get(name) -> Command | None` (case-insensitive, leading `/` allowed, aliases resolve), `__contains__`, `__len__`, `commands()` (group order, then name), `groups() -> list[tuple[str, list[Command]]]`, `names(*, aliases=True)`, `suggest(word) -> str | None` (difflib, cutoff 0.6, canonical name), `cli_entries() -> list[tuple[str, Callable[..., Any], str, str]]` (name, function, help, group; sorted). `add` raises `ValueError` for bad names, empty or multi-line help, an alias repeating the name, or any name, alias or CLI name already taken (the message names the owner); a failed `add` registers nothing.
- `load_registry(package: str = "tdp_cli.commands") -> CommandRegistry`: imports every module of the package whose name does not start with `_`, sorted by name, and calls its `register(registry)`; a public module without a callable `register` raises `RuntimeError`.

- `clean(text) -> str` (every non-printable character, ESC included, becomes `?`).

## Plug-in API for the view steps (build on this in parallel)

1. Add `cli/tdp_cli/commands/<area>.py` with `def register(registry: CommandRegistry) -> None` that calls
   `registry.add(Command(...))` (optionally with `cli=<Typer function>`) and/or
   `registry.add_cli(name, function, help=..., group=...)`. The module is discovered automatically. Never edit
   `main.py`, `registry.py`, `shell.py`, `session.py`, `options.py`, `output.py`, `theme.py` or another step's
   command module. Helper modules must start with `_` (`commands/_plan_render.py`); a public module without
   `register` makes startup fail.
2. Reserved names and aliases: analyze, analyse, history, open, load, status, model, settings, help, h, clear, cls,
   quit, exit, q. Reserved CLI names: analyze, history, model. Suggested groups: "Explore" (file table, file
   detail, graph, what-if), "Plan" (plan), "Report" (report, diff). Names match `^[a-z][a-z0-9-]{0,31}$`; help is
   one line; usage starts with `/<name>`.
3. Handler: `def handler(session: Session, args: Sequence[str]) -> None`. Parse with
   `parse_args(args, values=("--budget",), flags=("--all",), max_positionals=1)`. Raise `UsageError` for bad input
   (the shell prints it plus `Usage: <usage>`) and `CliError(message, hint=...)` for failures; never print
   tracebacks. Set `needs_analysis=True` to get the standard "No analysis is loaded" refusal, then
   `loaded = session.require_analysis()`. Ctrl+C inside a handler prints "Cancelled." and keeps the shell open.
4. Data: `loaded.meta` (`AnalysisMeta`) and `loaded.result` (`AnalysisResult`): `files` in priority order,
   `features` indexed by path (89 float32 columns), `extras[path]` (functions, dependents, dependencies,
   test_importers, commit_activity, cost), `graph`, `plan`, `stats`. `loaded.file(path)` finds one score.
   `Path(loaded.meta.repo_dir)` is the work tree, bare repository or mirror for git commands (through
   `tdp_core.mining.git.run_git`, imported inside the function). `session.bundle()` returns the `Bundle` for
   what-if (warn when `loaded.meta.model_version != session.model.version`). Plan rebuild with a new budget:
   `make_plan(result.files, result.features, {p: e.cost for p, e in result.extras.items()},
   import_graph_from_edges(result.graph.edges), budget, DEFAULT_SETTINGS.min_plan_priority)`; the default
   budget is `session.prefs.budget_hours`.
5. Output: print to `session.console` with `theme` helpers (`band_text`, `format_risk`, `format_hour_range`,
   `make_table`, `make_panel`, `notice`, `error`, `success`, `activity`, `clean`, `session.glyphs`) and
   `output` helpers (`files_table`, `band_counts`, `critical_hours`, `top_reason`). Repository strings (paths,
   reasons, names, commit text) always go through `clean()` into `rich.text.Text`, never into markup. Import
   pandas, tdp_core.analyze, tdp_core.contracts, tdp_core.mining and tdp_core.model inside functions (startup test
   forbids them at import time); types go under `TYPE_CHECKING`.
6. Completion: `complete=complete_analysis_paths` for file arguments, or
   `chain(options_completer("--budget"), complete_analysis_paths)`.
7. Typer subcommand: parameters in `Annotated` style with `ctx: typer.Context` first, then
   `target: TargetArgument = "."`, `ref: RefOption = None`, `model_dir: ModelDirOption = None`,
   `dev_model: DevModelOption = False` and your own options; `Literal[...]` works for choices. In the body:
   `session = cli_session(ctx, model_dir=model_dir, dev_model=dev_model)`,
   `loaded = cli_analysis(session, target, ref=ref)` (reuses the saved analysis of the same commit and model, so
   `tdp plan` after `tdp analyze` costs about 3 s), then do the work inside `with cli_guard(session.err_console):`.
   Machine output goes to stdout with `sys.stdout.write`, progress and notices to stderr. Exit codes: 0 ok,
   1 runtime failure, 2 bad input, 130 cancelled. `from __future__ import annotations` is fine as long as every
   annotation name is imported at runtime (not under `TYPE_CHECKING`).
8. Tests: put them in `cli/tests/test_<area>.py` and reuse the fixtures of `cli/tests/conftest.py`:
   `entropiq_home` (autouse, fresh `ENTROPIQ_HOME`, `COLUMNS=200`, model env vars cleared), `dev_bundle_dir`
   (session), `dev_home` (demo bundle copied into the home), `sample_repo` (session RepoBuilder repository, 12
   modules `pkg/<alpha..mu>.py`, about 30 commits), `sample_result` (session, the analysis of `sample_repo`),
   `sample_loaded`, `console` (records text, width 120, no colour), `session` (interactive, demo model),
   `loaded_session` (with `sample_loaded` as current). Drive commands with `dispatch(session, "/plan --budget 10")`
   and read `session.console.file.getvalue()`; drive Typer with `typer.testing.CliRunner` and
   `build_app()` (`result.stdout` and `result.stderr` are separate).

## Behaviour notes

- Model resolution (first match wins): `--dev-model` together with `--model-dir` is a usage error (exit 2);
  `--dev-model`; `--model-dir`; `$TDP_MODEL_DIR`; `models/production.json` found by walking up from the package,
  whose `version` is loaded from its `uri` when that is a local folder (absolute, relative to the repository
  root, or `file://`, Windows drive letters included) or from a folder named after the version under
  `$TDP_MODELS_DIR`, `<home>/models` or `<repo>/models` (the folder's `metadata.json` must have that version);
  otherwise the demo bundle with the reason ("no production model has been published yet", "production model X is
  not on this machine", "models/production.json is unreadable", "no models/production.json found"). An explicit
  folder that is not a bundle fails with exit 2. Today `production.json` has a null version, so the demo model is
  used and the yellow notice is shown.
- Home layout (`$ENTROPIQ_HOME` or `~/.entropiq`): `history`, `settings.json`, `models/dev/`,
  `models/<version>/`, `analyses/<slug>/<sha>.json` (`{"schema": 1, "result": to_jsonable(result)}`),
  `<sha>.features.parquet`, `<sha>.meta.json` (written last; `/history` reads only these), `mirrors/<host>/<owner>/<name>.git`,
  `cache/szz/<slug>/`.
- Slugs: URLs give `owner__name` on github.com (lower case) and `host__owner__name` elsewhere; local paths give
  `<folder name>-<8 hex of the path hash>`.
- A saved analysis is reused when slug, commit and model version match (`--fresh` forces a run). The reused plan
  keeps the budget it was made with.
- `tdp analyze --format json` document (`entropiq.analysis.v1`): `{"schema", "repo", "source", "kind", "ref",
  "sha", "analyzed_at" (ISO with Z), "model_version", "demo_model", "extractor_version", "summary": {"files",
  "critical", "high", "medium", "low", "critical_hours"}, "files": [{"rank", "path", "priority", "band", "risk",
  "risk_low", "risk_high", "cost_hours", "cost_low", "cost_high", "debt_types", "top_reason", "reasons"}]}`;
  `--top 0` lists every file, the default is the `top` setting (20). `entropiq history --format json` is a list of
  `AnalysisMeta.to_dict()` plus `number`; `entropiq model --format json` has version, kind, demo, source, reason,
  path, created_at, training_rows, metrics, n_features, extractor_version, code_git_sha.
- URL input: https on github.com or gitlab.com only (P5.5), `github.com/owner/name` without a scheme is accepted,
  `--ref` goes through `validate_ref`; local repositories accept any revision (`HEAD~10`) and a subfolder analyses
  its repository. An existing mirror is reused when DNS or the fetch fails (notice shows when it was fetched); a
  failed or cancelled first clone leaves no folder behind.
- `ENTROPIQ_DEBUG=1` prints tracebacks of unexpected errors and enables debug logging.

## Deviations from the plan and why

1. Orchestrator scope change: a full interactive shell on top of the planned Typer commands. `tdp plan`, `tdp diff`
   and `tdp report` move to the view steps (they register through the same registry); the JSON and Markdown output
   of `tdp analyze` lives in `tdp_cli.output` because the report writers were not on main when this step started.
2. No release download and no sha256 check: nothing is published yet and the GitHub Action step owns release
   assets; local bundles are matched by the version in their `metadata.json`.
3. `ENTROPIQ_HOME` overrides `~/.entropiq` (tests, CI, the Action) instead of `~/.cache/tdp`.
4. The model is resolved at startup from JSON only and XGBoost loads on first use, so startup stays fast; a demo
   bundle that is not built yet shows "not built yet" in the version line.
5. Saved analyses are reused (same slug, commit and model version); `--fresh` runs again.
6. Ctrl+C: commands run in the main thread and `KeyboardInterrupt` is caught per command; an analysis may finish its
   current git call or worker batch before stopping.
7. Interactive arguments use shlex with escapes disabled so Windows paths work; quote paths with spaces.
8. A non-terminal stdin uses a plain line loop instead of prompt_toolkit (pipes, CI, mintty).
9. URLs follow P5.5 (allowlist, `validate_ref`); no pre-clone size check on the user's own machine; mirrors are
   reused offline.
10. Mirrors live at `mirrors/<host>/<owner>/<name>.git` with absolute paths (P5.5 known issue 6).
11. The static parse cache is off (`cache=None`, P5.2 Windows note); SZZ results are cached per repository.
12. `--dev-model` beats `TDP_MODEL_DIR`; an explicit model folder that is not a bundle fails instead of silently
    using a demo model.
13. A sidecar `<sha>.meta.json` keeps `/history` free of pandas.
14. `/clear` keeps the loaded analysis and redraws a one-line header.
15. Settings are limited to `budget_hours`, `top` and `jobs`.
16. Repository strings are sanitised before display (terminal escape injection from untrusted repositories).
17. Bare words that name a command run it (`help`, `exit`); other text without `/` gets a hint.
18. Added `py.typed` so other packages can type-check against `tdp_cli`. Plain `uv run mypy cli/tdp_cli` reports
    "found twice under different module names" because of the root mypy settings; use
    `MYPYPATH=cli uv run mypy cli/tdp_cli` (clean with default settings).
19. The logo uses ASCII letters at 61 to 63 columns instead of the one-word logo (it fits).

## Known issues / limitations

1. Ctrl+C during an analysis on Windows also reaches the parse worker processes; the shell survives and prints
   "Cancelled." (or an "Unexpected error" line if the worker pool reports a broken pool first).
2. prompt_toolkit is exercised through pipe input in tests; the interactive look was checked only through
   the plain-mode transcript here (no TTY in the build agent).
3. Saved analyses are never pruned; delete `<home>/analyses/<slug>` by hand.
4. Two processes building the demo bundle at the same moment can race (each builds into its own temporary folder;
   the second rename fails with a clear error and a rerun works).
5. The demo notice is also printed by `entropiq history` (stderr), which does not use a model.
