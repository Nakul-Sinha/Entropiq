- Result as built:
  - `sha` = full sha of the resolved commit; `analyzed_at` = now in UTC without microseconds; `model_version` = `bundle.version`; `extractor_version` = `EXTRACTOR_VERSION`.
  - `files`: one `FileScore` per parsed non-test file, sorted by (-priority, path). `score` = ranker margin, `priority` from `priority_from_scores`, `band_for`, `risk`/`low`/`high` from `bundle.calibrator.predict`; `reasons`, `mitigations`, `debt_types`, `shap_by_family` from `Explainer(bundle).explain(features)` (repository baseline).
  - `features` = `build.features.set_index("path")[FEATURE_INPUT_COLUMNS]`, sorted by path (not in `files` order), float32, finite.
  - `extras` keyed by path in path order: `blob_sha` from `build.blob_shas`; `functions` from `build.syntax`; `dependents` = sorted non-test importers; `dependencies` = sorted imported files; `test_importers` = sorted test importers; `commit_activity` = 24 `("YYYY-MM", n)` pairs ending with the month of T (P2.1 `commit_activity`); `cost` = `estimate_cost(row, syntax, build.clones[path], bundle.cost_model)`.
  - `graph`: nodes in `files` order (`sloc`, `dependents` = `transitive_dependents` as ints); import edges between ranked files sorted by (source, target) with weight 1.0, then the hidden coupling edges, sorted.
  - `plan` = `make_plan(files, features, costs, build.import_graph, budget, settings.min_plan_priority)`; each `PlanStep.cost` is `extras[path].cost`.
  - `stats` keys in order: `n_files`, `n_test_files`, `n_skipped`, `skipped` (path to reason), `n_commits`, `history_since` (ISO with Z, or null), `history_truncated`, `shallow`, `snapshot_time`, `n_bugfix_commits`, `n_szz_fixes` (fixes with at least one traced row), `timings_s` (all seven stages, seconds), `mine_timings_s` (`history`, `bugfix`, `szz`), `total_s`. JSON types only (`json.dumps(..., allow_nan=False)` is tested).
  - Progress messages: "Mined N commits and found M bug fixes", "Parsed the source files", "Built the import and co-change graphs", "Computed the file features", "Scored N files", "Explained N files", "Planned N fixes within B hours" (singular forms handled).
- Deviations from the plan and why:
  - D1. T = the analysed commit's committer time (`git log -1 --format=%ct`), not the wall clock (P1.1 note) or the author time: the result depends only on the commit, and committer dates are the section 15.5 rule. `since` = T minus `history_window_days`, applied by `git --since` to committer dates; a cutoff before 1973-03-03 (Unix time below 100,000,000) mines everything, because git reads a shorter `@<seconds>` as a date.
  - D2. `Snapshot(<folder name without .git>, 0, T, <full sha>)` is built directly instead of the old mode `snapshot_at` (P2.7 note); `reachable` = every mined sha for `build_features` and `commit_activity` (section 15.5, P2.1 note).
  - D3. `sha` may be any revision (`rev-parse --verify --quiet --end-of-options <rev>^{commit}`, tags peeled); `result.sha` is the full sha. An unknown revision, a tree or a blob gives `GitError` "does not name a commit" (return code 1); other git failures propagate unchanged.
  - D4. `satd_model=None` loads `load_default_classifier()` (the weights used for training features, P2.4 and P2.7 notes), unlike `build_features` where None means keyword counting; pass a classifier to override.
  - D5. Extra keywords: `jobs` (parse workers, blame threads, SZZ threads; 0 means `os.cpu_count()`; default 4 per section 15.3) and `szz_cache_dir` (P2.6 per-fix cache, one folder per repository).
  - D6. Progress fires when each stage finishes, with the percentages above (build stages through `build_features(on_stage=...)`). An exception from the callback stops the analysis and propagates unchanged (cancellation). There is no 0 or 100 event; the caller sends its own.
  - D7. Bug fixes are keyword only (`classify_bugfix(commits, file_changes)`) and SZZ runs for the newest `settings.inference_szz_max_fixes` fixes, both inside the mine stage (`mine_timings_s` splits it).
  - D8. Hidden coupling: one edge per unordered co-change pair among ranked files without an import edge in either direction, pointing along the stronger direction (higher confidence, ties to the source that sorts first), weight = that confidence (P2.2 note).
  - D9. A commit without rankable files returns empty `files`, a zero-row frame with the 89 columns, empty `extras` and `graph`, an empty plan, and still sends all seven events.
  - D10. Checks before any git command: budget finite and >= 0 (0 gives an empty plan), `jobs >= 0`, `check_rev`, non-negative window and caps, positive parse limit, existing directory. Bundle templates and cost values are checked when first used (explain and plan stages), so a commit without rankable files never reaches them.
  - D11. Shallow clones are analysed with a warning and `stats["shallow"] = true`.
  - D12. `settings.analysis_timeout_s` is not enforced inside `analyze` (the worker's Celery limits do it).
  - D13. Importing `tdp_core.analyze` loads neither xgboost nor shap (`Bundle` only under `TYPE_CHECKING`; shap loads with the first `Explainer`); tested in a subprocess.
  - D14. The analysis is read-only for `repo_dir` (tested: `git status` and refs unchanged); it writes only to `cache` and `szz_cache_dir`. Branch name from the orchestrator.

- Known issues / limitations:
  1. Inference mines at most 1,095 days and 20,000 commits before T while training uses the whole history (section 3.1 design), so `age_days`, `commits_total`, `n_authors` and the defect history of old files saturate (the `pct_` copies soften it).
  2. `history_truncated` is also true when the window holds exactly `max_commits` commits.
  3. On this Windows laptop a fresh `DiskStaticCache` slows parsing (pylint parse 39.6 s cold and 39.8 s on the first re-read, against 3.2 s without a cache; the antivirus effect P2.7 measured). Linux and `PostgresStaticCache` are not affected.
  4. The first analysis in a process pays `import shap` (3 to 8 s).
  5. SZZ dominates cold mining; `szz_cache_dir` cuts reruns to about 2 s.
  6. Parse limits are soft in-process (P2.7) and `analysis_timeout_s` is the caller's job.
  7. Dev bundle rankings are synthetic.
