- Behaviour:
  - State at T = the first commit with committer date `<= T` met when walking the first-parent chain of the default branch back from its tip (`git rev-list -1 --first-parent --before="@<ts> +0000" --end-of-options <ref> --`). It may be a merge commit. History up to T = `reachable_shas(repo_dir, state)` = non-merge commits reachable from it = the shas of `mine_history(repo_dir, state)`.
  - `default_branch` reads HEAD's symref and strips `refs/heads/` (full ref if HEAD points elsewhere). Raises `GitError` for a detached HEAD or when git cannot run. An unborn branch (no commits) is still returned; `snapshot_sha` then raises `GitError`.
  - `snapshot_sha`: `t` must be aware (`ValueError` otherwise) and is floored to whole seconds (exact, committer dates are whole seconds). `branch=None` means HEAD's branch; a plain name is qualified as `refs/heads/<name>` (a same-named tag cannot shadow it); a name starting with `refs/` is used as is; other revisions are not accepted. `t` before 1970 returns `None` without running git. Unknown branch raises `GitError`; option-like branch raises `ValueError`. Monotone: for `t2 >= t1` the result at `t2` equals or is a first-parent descendant of the result at `t1`, so the reachable sets are nested.
  - `reachable_shas` raises `ValueError` for option-like input and `GitError` for an unknown sha.
  - `make_snapshots(..., repo_dir=...)`: same T schedule as the author-date mode (first author time + `min_history_days`, step `snapshot_step_days`, keep `T + horizon_days <= last author time`). HEAD is resolved once, one `rev-list` per T. A T with no state is skipped (debug log) and indexes stay contiguous (0..n-1). No git runs when the schedule is empty. `snapshot_step_days < 1` still raises `ValueError` first in both modes. `GitError` for a detached HEAD.
  - `snapshot_at(..., repo_dir=...)`: ignores `commits`; returns `Snapshot(repo, 0, t in UTC, snapshot_sha(repo_dir, t))`; raises `ValueError` when `t` is naive or no state exists.
  - `ensure_mirror`: new mirrors are `git clone --bare --no-hardlinks -- <url> <dest>`, then `remote.origin.fetch` is stored as `FETCH_REFSPEC`. Existing mirrors are updated with `git --git-dir=<dest> fetch --prune --tags origin +refs/heads/*:refs/heads/*` (refspec on the command line). Branches deleted upstream are pruned, tags are added but never pruned, refs outside heads and tags that an old mirror already has stay, HEAD is set at clone time only. `--git-dir` and `--` before the URL are kept.

- Deviations from the plan and decisions where 15.5 is vague:
  - D1. Updates pass `+refs/heads/*:refs/heads/*` on the command line instead of relying on stored config. One code path refreshes prefetched, new and old `clone --mirror` mirrors, never fetches `refs/pull/*`, and never rewrites an existing mirror's config.
  - D2. "then fetch refspec" is read as "then store the fetch refspec": no second fetch runs after `clone --bare`, which already holds all branches and tags.
  - D3. Pull request refs that an old full mirror already holds are not deleted (destructive and not needed for correctness).
  - D4. Tags are still fetched but not pruned, matching the prefetched mirrors and P1.1's test.
  - D5. `default_branch` returns the short name from HEAD's symref, or the full ref if HEAD points outside `refs/heads`.
  - D6. `snapshot_sha` qualifies plain names as `refs/heads/` and uses `--before="@<ts> +0000"`: git misreads a bare `@<ts>` for ts before 1973-03-03 and silently returns the branch tip (reproduced, regression test included). A `t` before the epoch returns `None`.
  - D7. The `repo_dir` schedule is the same author-time grid as the old mode, so both modes share T values. Measured fact b below makes the horizon check equivalent or conservative.
  - D8. Ts with no state are skipped instead of raising; indexes stay contiguous.
  - D9. `snapshot_at` ignores `commits` in `repo_dir` mode.
  - D10. No `branch` keyword on `make_snapshots`/`snapshot_at` (the plan asks only for `repo_dir`); use `snapshot_sha(..., branch)` for other branches.
  - D11. No re-exports added to `tdp_core/mining/__init__.py` (P1.1's file; 15.4 says import from modules).
  - D12. The git rule is kept despite old first-parent date inversions (see known issues); P2.8 uses only the 8 most recent snapshots.
  - D13. Repository discovery stays cwd-based, like the P1.1 readers.

- Known issues / limitations:
  - Pre-2016 first-parent date inversions (fact c) can make an old state contain commits committed after T (69 commits in one 2010 pip snapshot). Recent snapshots are unaffected.
  - HEAD of a mirror is not updated if upstream renames its default branch; the old branch is pruned on the next fetch (checked), HEAD is left dangling and `snapshot_sha(mirror, t)` then raises `GitError`. Fix by hand with `git --git-dir=<mirror> symbolic-ref HEAD refs/heads/<new>`.
  - An old `clone --mirror` mirror keeps the `refs/pull/*` refs it already has (no new ones are fetched).
  - Repository discovery is cwd-based like the P1.1 readers: a wrong `repo_dir` makes git walk up to an enclosing repository, and under `C:/Users/nakul` (which has a `.git` owned by SYSTEM) it fails with "dubious ownership". Tests never rely on git's behaviour in a non-repo directory.
  - P1.1's `mine_history(since=)` passes `--since=@<ts>` without a zone, which git misreads before 1973 (harmless in practice; that file is P1.1's).
- Notes for dependent steps (by ID):
  - P2.1, P2.2: pass `reachable=reachable_shas(repo_dir, snapshot.sha)`. It is a `frozenset` (an `AbstractSet`) of non-merge shas, equal to the shas of `mine_history(repo_dir, snapshot.sha)`.
  - P2.6: use `end = snapshot_sha(repo_dir, snapshot.time + timedelta(days=settings.horizon_days))`. It is never `None` when the state at T exists, and `reachable_T <= reachable_end`. Window commits are `reachable_end - reachable_T`; they can have `author_time <= T` (late merges and rebases), so do not time-filter them.
