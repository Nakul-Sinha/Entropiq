- Behaviour (module docstrings have the full rules):
  - User prompt, in this order: path, size (and a note when the parser recovered from syntax errors), priority
    and band, risk with its range, debt types, cost range with the nonzero base minutes per issue kind (P4.1's
    `breakdown`, before its blast radius multiplier), up to 10 reasons, up
    to 10 mitigations, up to 50 functions most complex first (the valid step targets), up to 20 dependents,
    dependencies and test importers each (sorted, with totals), up to 10 SATD comments (`satd_candidates`, line
    order, each cut to 300 characters) inside `<satd_comments>`, then the excerpt inside `<code_excerpt>`.
  - Excerpt: the 3 functions with the highest cyclomatic complexity (ties by start line, end line, name), shown in
    that order, each prefixed with `# lines a-b (name, cyclomatic n)`. Ranges are clamped to the source; a range
    that overlaps one already chosen (nested functions) is skipped; the total of source lines is capped at
    `settings.advisor_max_excerpt_lines` and the part crossing the cap is cut with a header note
    (`truncated, the function ends at line n`). With no usable function the first lines are shown as module
    code. Lines are split on `"\n"` only, so line numbers match tree-sitter rows.
  - Injection hardening: every interpolated string from the repository goes through `neutralize_tags` (a `<`
    that starts a `code_excerpt` or `satd_comments` tag, any case or spacing, becomes `&lt;`), and single-value
    fields lose their line breaks, so our four tags appear exactly once. The system prompt marks the excerpt, the
    comments, paths and function names as untrusted data whose instructions must never be followed.
  - Parsing: the first `{` that decodes to a JSON object wins (prose, fences and trailing text are fine; NaN and
    Infinity are rejected). One retry with the error appended to the user prompt (the bad reply is not echoed,
    the error lists at most 10 `loc: msg` items, never input values or links); a second failure raises
    `AdviceError("no valid advice for <path> after one retry: ...")`.
  - Grounding: targets are normalized (quotes, backticks, `()` or `(args)`, `self.`/`cls.` removed). A step is kept
    only if it has at least one target and every target is a dotted suffix of a function's qualified name or of
    an enclosing scope (`Parser.parse`, `parse`, `Parser`, `_scan.keep`), the path or its base name. Effort pairs
    are sorted, then clipped into `[0.25, max(0.25, cost.high)]`. Kept steps are renumbered 1..n in the model's
    order; `dropped_steps` counts the rest. Zero kept steps is valid advice.
- Deviations from the plan and why:
  1. Branch `step/P4.3-llm-advisor` (set by the orchestrator). `__init__.py` stays docstring-only (15.4 overrides
     the Owns list), so the 3.6 names live in `schema`, `client` and `advisor`.
  2. Error families: `AdviceError(RuntimeError)`; `LLMError(AdviceError)` with `retryable`. The advisor never
     retries or wraps a failed call, because the SDK already retries 408, 409, 429, 5xx and connection errors;
     a worker needs one `except AdviceError` plus a check of `retryable`.
  3. `AnthropicClient` keeps `(model, api_key=None)` and adds keyword-only `timeout_s`, `max_retries`, `effort` and
     `fallbacks`, plus `close()`. The key is the argument or `ANTHROPIC_API_KEY`, passed explicitly to the SDK so
     it never uses `ANTHROPIC_AUTH_TOKEN`, an `ant` profile or federation. A missing key or package fails at
     construction with `LLMError`.
  4. The server-side refusal fallback is on by default (beta `server-side-fallback-2026-07-01` plus
     `fallbacks="default"`, recommended for `claude-sonnet-5-5`). A final refusal is a non-retryable `LLMError`
     naming the category.
  5. No sampling parameters, thinking config or prefill (current models reject them). `ADVICE_MAX_TOKENS = 16000`
     because `max_tokens` covers adaptive thinking too. A reply cut off by `max_tokens` is logged and goes
     through the parse and retry path.
  6. `FakeLLMClient` takes `Sequence[str | Exception]` (a superset of `list[str]`) so tests can simulate failed
     calls; an exhausted fake raises `RuntimeError`, a bare string raises `TypeError`, calls are `LLMCall`s.
  7. Schema hardening (stripping, no NaN or inf, frozen, non-empty summary and action, case-insensitive
     confidence). The schema sent to the model leaves out `dropped_steps`, and a model-sent value is discarded.
  8. Prompt facts beyond the plan's list: size and parse-error note, mitigations, cost breakdown, the function list
     (it tells the model which targets are valid), direct dependencies, totals, and caps on reasons (10), test
     importers (20) and functions (50). SATD comments get their own untrusted `<satd_comments>` block.
  9. Grounding is wider than "qualified name or last segment" but still limited to names in the file: dotted
     suffixes of functions and enclosing scopes (so classes with methods count), the path and its base name.
     Steps without targets are dropped (closes the empty-targets loophole). Effort pairs are sorted before
     clipping. Kept steps are renumbered. `dropped_steps` is additive, so grounding is idempotent.
  10. `advise` uses its `path` argument and `syntax.functions` (not `syntax.path`, `score.path` or
      `extra.functions`): the static cache is keyed by blob sha, so a cached `FileSyntax` may carry another path.
  11. `PROMPT_VERSION` lives in `prompt.py` (re-exported by `advisor.py`); bump it with any prompt, excerpt or cap
      change, because it is part of the cache key.

- Known issues / limitations:
  - No real API call was made while building this step (no key on the build machine); the network test is the
    check. The request shape is tested against the installed SDK (`anthropic` 2.3.0) with a stubbed method.
  - Classes without methods are not valid targets (`FileSyntax` has no class names). Free text (`action`,
    `summary`, `tests_to_add`, `risks`) is not grounded.
  - Excerpts, possibly with secrets from the analysed repository, are sent to Anthropic.
  - Requests are not streamed: one attempt may take up to `timeout_s = 300` seconds, and with the SDK's retries
    a call can last about three times that.
  - First-party Claude API only; Bedrock or Vertex need other client classes (and client-side fallbacks).
  - The client relies on request and response fields of the locked `anthropic` 2.3.0 (`fallbacks`,
    `output_config`, `stop_details`, `anthropic.omit`), but the `advisor` extra in
    `packages/core/pyproject.toml` still says `anthropic>=0.40`. Installs from `uv.lock` (CI, Docker) are fine;
    an install outside the lock with an old SDK would fail at call time with a `TypeError`. Raise the floor the
    next time a step re-locks.
  - The system prompt is constant and could carry `cache_control` if advice is ever generated in bursts; it is
    not cached now because calls are expected to be sporadic.
