## Public API added (exact signatures, module paths)

`tdp_cli.model`
- `HOME_POINTER: Final = "production.json"`.
- `installed_pointer(home: EntropiqHome) -> Path`: returns `home.models / HOME_POINTER`, the production pointer an
  installed command reads (a copy of `models/production.json`; a relative `uri` resolves against `home.root`).
- Private `_production(pointer: Path, base: Path, home: EntropiqHome, environ: Mapping[str, str], *, label: str)
  -> tuple[ModelChoice | None, str]` (was `_production(repo_root, home, environ)`). Candidates in order: the
  pointer's local `uri` (absolute, relative to `base`, or `file://`), `$TDP_MODELS_DIR/<version>`,
  `home.models/<version>`, `base/models/<version>`. The chosen `ModelChoice.reason` is `label`.
- `resolve_model` order is now: `--dev-model`, `--model-dir`, `$TDP_MODEL_DIR`, the checkout's
  `models/production.json` (reason `"models/production.json"`), then `<home>/models/production.json` (reason is
  that file's path), then the demo model. A missing or broken home pointer falls back to the demo model with the
  same reasons as before (`"no production model has been published yet"`, `"production model X is not on this
  machine"`, `"<pointer> is unreadable"`); no pointer anywhere keeps `"no models/production.json found"`.

`tdp_cli.main.build_app`
- `add_completion=True`: `--install-completion` and `--show-completion` are root options.
- Subcommands are registered sorted by `(group_rank(group), name)`, so `--help` shows the panels as Analysis,
  Explore, Plan, Report, Session. `CommandRegistry.cli_entries()` is unchanged (still sorted by name).

`tdp_cli.commands._views.ranked_table` and `tdp_cli.output.files_table`
- The File column no longer has `no_wrap=True` and Top reason no longer has `min_width=20` (both keep
  `overflow="fold"`). Before, the table could be wider than the console and rich cropped each line, so
  `"Very large file: 892 lines"` showed as `"Very large file: 8"` at 120 columns.

## Deviations from the plan and why
- The plan section for this step asked for final experiments and `docs/RESULTS.md`. The orchestrator moved
  experiments after V1 and replaced the results report with `docs/DEMO.md`; the README carries the recorded numbers
  from the dataset, baselines, training, calibration and registry handoffs.
- Small fixes to files of the P7.1 and P7.8 command line steps (model resolution, completion, help order, table
  widths). They were needed for a global install and for a demo without cropped text; each has a test.
- Global install on the laptop: `uv tool install --reinstall --link-mode copy ./cli --with anthropic` with
  `UV_CACHE_DIR=G:/uv-cache` (the default cache fails with "too many temporary files") and
  `UV_TOOL_BIN_DIR=C:/Users/nakul/AppData/Roaming/SPB_Data/.local/bin` (already on the user PATH; uv's default
  `C:\Users\nakul\.local\bin` is not). `--reinstall` is needed because uv caches local builds by pyproject mtime.
  `--with anthropic` makes `/advise` work once a key is set. No PATH or profile was edited and
  `--install-completion` was not run on the laptop.
- The tool environment is at `C:\Users\nakul\AppData\Roaming\uv\tools\tdp-cli`.

  into a few characters). No text is lost; DEMO.md asks for 140 columns or more.
