- SZZ rules as built (module docstring of `szz.py`):
  1. Diff: one `git diff-tree -r -p -M -U0 -w --inter-hunk-context=0` of the fix against its first parent, with the diff algorithm (Myers), path quoting, `a/` and `b/` prefixes, external diff, textconv and relative paths pinned. Parent-side ranges `(a, b)` with `b > 0` are kept. A root commit and a merge print nothing.
  2. Only modified files are traced: added, deleted, binary, pure renames, mode-only changes, symlinks (120000) and submodules (160000) give no lines. A pair is traced when `is_source` holds for its old or new name. A renamed and modified file is traced under its old name.
  3. Blame: one `git blame --line-porcelain -w <fix>^ -L a,+b ... -- <path>` per file (at most 200 ranges per call), `blame.ignoreRevsFile` reset, `--literal-pathspecs`. Names that are not valid UTF-8 are skipped (they cannot be passed back to git).
  4. Content filter on blame's own copy of each line: blank, comment-only (`#` after strip, CRLF safe) and import lines (`import x`, `from x import y`) are dropped. `importlib.reload(x)`, `from_date = 1` and `x = 1  # c` are kept.
  5. Inducing commits in `bulk_shas` are dropped, and so are lines authored strictly after `not_after` (a line exactly at `not_after` is kept).
  - `szz_table`: fixes are `is_bugfix` rows (null is false, first row per sha) whose sha is a non-bulk commit of `hist`, newest first by (author time desc, sha asc), capped by `max_fixes`. `issue_created_at` (optional column) is `not_after`; the bulk shas of `hist` are `bulk_shas`. One `git cat-file --batch-check` call checks every fix sha up front and raises `GitError` naming the count and the first shas when any is not a commit of `repo_dir`. After that, a `GitError` for one fix (including `TransientGitError` timeouts) is logged as a warning and the fix is skipped and not cached. Output rows: one per distinct (fix_sha, path, inducing_sha), sorted by (fix_time, fix_sha, path, inducing_sha), identical for any `jobs` and with or without the cache. No git runs when no fix is selected.
  - Cache: `cache_dir/<sha[:2]>/<sha>.v1.json` = `{"fix_sha", "version", "lines": [[path, line, inducing_sha, author_unix], ...]}` holding the traced lines before the bulk and `not_after` filters, so one cache serves the issue-aware and the keyword-only bug-fix tables. Written atomically (unique tmp name, `os.replace`); write failures are logged at debug level; missing, unreadable or malformed files and sha or version mismatches are recomputed. The cache assumes one `is_source`: use one `cache_dir` per predicate.
- Label and feature definitions (module docstring of `labels.py`):
  - T is `snapshot.time` (aware, whole seconds). Time mode (both reachable sets None): prior history P = `author_time <= T`, window W = `T < author_time <= T + horizon_days`. Reachable mode (both sets given, section 15.5): P = `reachable_T`, W = `reachable_end - reachable_T`, no time filter (late merges authored before T are window commits). Exactly one set raises `ValueError`, and so does `reachable_T` not being a subset of `reachable_end`.
  - Commit identity: `(author_email, author_time, subject)`; cherry-picked and rebased copies share it. A sha missing from `hist` is its own identity. `prior_ids` = identities of the `hist` commits in P.
  - W*: non-bulk `hist` commits of W whose identity is not in `prior_ids`, one per identity (smallest sha).
  - An inducing commit is before T when its sha is in `reachable_T` (time mode: `inducing_time <= T`) or its identity is in `prior_ids`. A fix is in the window when its sha is in W (time mode: `T < fix_time <= end`) and its identity is not in `prior_ids`.
  - Window names: `start(f) = {f} | {names in lineage_at_T[f] that no file alive at T uses}` (alive = keys of `lineage_at_T` plus `paths`); `names_W(f)` = closure of `start(f)` under the rename edges `old_path -> path` of every change row of every W commit (bulk included).
  - `latent_defects(f)` = distinct identities of window fixes with at least one szz row whose `path` is in `names_W(f)` and whose inducing commit is before T. `future_churn(f)` = `file_touches(hist, snapshot, names_W, targets, reachable=W*)` churn summed per file (non-bulk; a change row matches on `path` or `old_path`; a row counts once per file). `pain = pain_from_counts(latent, churn, settings.gamma)` with the median over the query, `grade = grades_from_pain(pain)` on the float32 pain, `has_latent_defect = latent > 0`.
  - `prior_bugfix_commits(f)` = distinct identities among the non-bulk prior fixes S (P and `is_bugfix`) that touch `names_P(f) = lineage_at_T.get(f, frozenset()) | {f}` (through `file_touches(..., reachable=reachable_T)`). `prior_latent_bugs(f)` = distinct identities of the fixes in S' (S, or the newest `max_fixes` of S by author time desc, sha asc) with an szz row whose `path` is in `names_P(f)`. szz rows of fixes outside S are ignored.
- Deviations from the plan and decisions where it is vague:
  - D1. Thread pool instead of a process pool: the work runs in git child processes, and threads avoid pickling `is_source` and re-importing pandas per process under Windows spawn.
  - D2. `git diff-tree` with pinned options instead of `git diff fix^ fix`: the same hunks for a non-merge commit, root commits and merges need no special case, and the user's config cannot change hunks.
  - D3. `is_source` holds for either name of a file pair, as in P2.5's `source_commits`.
  - D4. Added, deleted, binary, symlink, submodule and pure-rename entries give no lines. Blaming a whole-file deletion would mark every commit that ever touched the file. `future_churn` still counts deletions.
  - D5. The content filter reads blame's own content lines (no extra blob read).
  - D6. Bulk and `not_after` use author time; a line exactly at `not_after` is kept.
  - D7. Lines that blame attributes to merge commits (conflict resolutions) stay in the table.
  - D8. Table grain is one row per (fix, path, inducing commit) plus `n_lines`.
  - D9. Optional per-fix JSON cache of raw lines (the plan's "caches results").
  - D10. One existence check up front (fails fast on a wrong `repo_dir` or a stale table), then per-fix failures are warned about and skipped. `timeout` is 300 s per git call.
  - D11. Labels map files with the forward rename closure instead of "lineage at each fix time": computing lineage per fix costs a full `path_lineage` walk per fix, and intersecting name sets double counts reused names (flask `app.py` split into `sansio/app.py`, also seen by P2.2 in celery and pylint). Pre-T names no live file uses are kept, so late-merged stale branches still count.
  - D12. Commit identity dedup for latent defects, churn and both D features (P2.5 recommended it). A window copy of a prior commit is not new work.
  - D13. Reachable sets are both or neither and must be nested; the time mode keeps the plan's original rules for simple callers and tests.
  - D14. `defect_history_features` accepts `reachable_end` as section 15.5 lists, but only checks it (it needs `reachable_T` and must contain it) and never reads it, because a feature must never see the label window. `reachable_T` alone is enough (P2.7 only has `reachable_T`). It gains `max_fixes` for train/serve parity.
  - D15. `defect_history_features` counts only szz rows of fixes that the given bug-fix table marks, so a keyword-only table can be combined with a broader szz table.
  - D16. The label frame is flat with exact dtypes; `index_frame` is shared with P2.7.
  - D17. Grades are computed on the float32-rounded pain.
  - D18. Extra public helpers (`pain_from_counts`, `grades_from_pain`, `reachable_window`, `index_frame`, the constants) and optional keywords on the planned functions; all additive.
  - D19. Branch name is the orchestrator's (`step/P2.6-szz-labels-and-defect-history-features`).
  - D20. Builder addition: an inducing commit whose identity is in `prior_ids` also counts as before T, so a fix of lines that a window copy of a prior commit wrote is a latent defect (the original lines existed at T). In time mode this changes nothing, because copies share their author time.

- Known issues / limitations:
  - Name-set semantics: a name held by two files at different times counts for both (for example a window rename into a name that another live file used at T).
  - In reachable mode, lines that blame attributes to merge commits (conflict resolutions) never count as before T, because reachable sets hold only non-merge commits.
  - Deleted files are not traced (D4); wide fixes mark every touched file.
  - Bulk inducing lines are dropped rather than re-blamed past the bulk commit (`git blame --ignore-rev` would be an improvement); at inference, bulk commits older than the mined window are unknown.
  - **Population note for P2.7 and the P1.2 owner:** pylint's `doc/data/messages/<x>/<message>/{good,bad}.py` examples pass `default_is_source`, which is why its files per query jump from 315 to 859 and more after 2022 (most of them have no activity and grade 0). Excluding example or documentation folders belongs to `tdp_core.parsing.filters`.
