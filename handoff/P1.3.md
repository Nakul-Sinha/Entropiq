- Contract changes: none
- Deviations from the plan and why:
  - Edge cases the plan leaves open, decided here: a file with at least k but fewer than k + w - 1 tokens (so fewer than w k-grams) is one winnowing window, so it still gets exactly one fingerprint. Every occurrence of a clone hash is marked, including an occurrence that only overlaps another occurrence in the same file (its tokens are the same content).
  - k-gram hashes are computed by Horner's rule over all positions at once with numpy (k vector passes, exact 64-bit modular arithmetic) rather than a per-token rolling loop. The values are identical to the rolling recurrence; a test checks this against a pure Python rolling hash for k in {1, 2, 7, 50, 200}.
  - Raises `ValueError` if `clone_k` or `clone_window` is below 1, or if a file's `tokens` and `token_lines` lengths differ.
- How to verify (commands):
  - `uv run pytest packages/core/tests/parsing/test_clones.py -q`
  - `uv run pytest -q && uv run ruff check . && uv run ruff format --check . && uv run mypy packages/core`
- Measured results:
  - 2,000 files x 500 tokens (1,000,000 tokens, 200 planted clones): 1.27 to 1.90 s per call over 5 runs on the Windows dev laptop (best 1.27 s), against the 10 s budget.
  - Line coverage of `clones.py` from its tests: 100%.
- Known issues / limitations:
  - Tokens of every file are compared regardless of `FileSyntax.language` (only Python exists today).
  - A long run of a short repeated pattern (for example a 200-token list literal `ID , ID , ...`) counts as a clone within its own file once its repeats are at least k tokens apart. That follows the plan's same-file rule; a 70-token run does not count.
  - Identical files reach `dup_ratio` of at least `1 - 2 * (w - 1) / n`, not exactly 1.0: winnowing can leave up to w - 1 tokens unmarked at each end.
