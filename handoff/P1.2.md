- Deviations from the plan and why:
  - Fixtures are stored as `fixtures/*.py.txt`, not `*.py`. `ruff check .`, `ruff format --check .` and
    `mypy packages/core` sweep every `.py` file under `packages/core`: the syntax-error fixture fails all three,
    and the others would be reformatted (losing deliberate layout) and type-checked as top-level modules.
    Excluding them in the root `pyproject.toml` would edit a P0.1 file, so the extension changed instead.
  - The parser is created once per thread (lazily, thread-local) instead of once per process: a tree-sitter
    `Parser` is not thread safe. Single-threaded callers still get exactly one parser.
  - Choices the 13 rules leave open (all covered by tests):
    - A `string` node is one leaf for SLOC (every line it spans counts, blank lines inside included) and one
      `"LIT"` token. f-string interpolations still count for complexity (they are real code).
    - Zero-width leaves (tree-sitter MISSING nodes from error recovery) give no SLOC and no token.
    - `line_continuation` (trailing backslash) counts for SLOC but is not a token (layout, like comments).
    - `FunctionInfo.start_line` is the `def` (or `async`) line, decorators excluded. `end_line` is the last line
      holding code: tree-sitter attaches trailing comments to the body, and they no longer stretch a function.
    - Cognitive complexity descends into nested functions (body one nesting level deeper, as rule 5 says) and
      nested classes (no extra level); lambdas add no nesting. Cyclomatic and max_nesting stop at nested
      functions and classes (rule 4), which report their own values.
    - max_nesting: a function with one `if` has 1; elif/else/except/finally/case bodies sit at their
      statement's level (a top-level `match` gives 1, not 2).
    - Cognitive nesting rises inside `if/elif/else/for/while/except/with/match` bodies only; `try` and
      `finally` bodies do not (rule 5 lists neither). `else_clause` adds 1 wherever it appears (if, for, while,
      try), as rule 5 is written.
    - params: the first parameter is dropped when named `self` or `cls` in any function, method or not; bare
      `*` and `/` separators are not parameters.
    - Comments: exactly one leading `#` is removed, then the text is stripped (`##  x` gives `#  x`).
    - `module_cc` ignores class bodies and default parameter values (they are inside class/function nodes);
      decorators of top-level definitions are module code.
    - `import a, b` gives one `RawImport` per module; `from x import y as z` records `y`; `__future__` imports
      are included; level = number of dots in the prefix.
    - `skip_reason` "first 5 lines" and "line" split on `\n` (a trailing `\r` is not content); line length is in
      decoded characters; the vendored check looks at every path component.

- Measured results:
  - Versions: tree-sitter 0.26.0, tree-sitter-python 0.25.0 (language ABI 15).
  - Node-type names: every name in the plan exists unchanged in tree-sitter-python 0.25.0. Worth knowing:
    there is no `except_group_clause` (`except*` is an `except_clause` with a `*` child); a `case` guard is an
    `if_clause` (so a guarded case adds 2 to cyclomatic: `case_clause` + `if_clause`); `else_clause` is shared
    by if/for/while/try; `async def/for/with` are the usual nodes with an `async` child.
  - Speed: a 1,008-line file parses in about 35 ms best, 40 ms median on the Windows dev laptop (tree-sitter
    itself is about 13 ms of that). The test threshold is 0.5 s.
  - Coverage of `tdp_core.parsing`: 98% (the 4 missed lines are defensive branches for broken trees).
- Known issues / limitations:
  - tree-sitter 0.26.0 bug: `Point.row` / `Point.column` return a dangling int for values above 256, which
    corrupts the heap and segfaults (seen on Windows). The plugin only indexes or unpacks points
    (`node.start_point[0]`); a regression test parses 900 lines and checks exact line numbers.
  - `settings.parse_timeout_s` is not enforced: `parse(path, source)` takes no settings. A caller that needs a
    hard limit can run the parse under its own timeout; `skip_reason` already drops files over 1 MB.
  - Metrics on error-recovered trees are best effort (`parse_error` is set).
  - `get_plugin` matches extensions case sensitively and does not handle `.pyi`.
  - mypy prints `unused section(s): ... tree_sitter.*` for the root `pyproject.toml` override, because tree-sitter
    ships its own types. Harmless; left for the owner of `pyproject.toml`.
