- Deviations from the plan and why:
  - Section 3.6 lists `build_import_graph(syntax_by_path)` and `graph_features(G, test_paths)`; the P1.4 step
    section lists `build_import_graph(syntax_by_path, is_test)` and `graph_features(G, settings)`. Implemented the
    step section. Test membership travels on the `is_test` node attribute, so `graph_features` needs no
    `test_paths`. The 3.6 table was not edited (scope of this step); the coordinator may want to align it.
  - Return and parameter types are written `nx.DiGraph[str]` because `types-networkx` makes `DiGraph` generic and
    `mypy --strict` rejects the bare name. Same graph object as the plan's `nx.DiGraph`.
  - Only paths whose components are valid Python identifiers are registered as modules (`scripts/my-tool.py`,
    `.github/x.py`, `a/b.c.py` cannot be imported by name). A root `__init__.py` has no module name.
  - Collision rule follows the plan ("prefer the shorter path", ties by lexicographic order), so `a/b.py` beats
    `a/b/__init__.py` and `pkg/m.py` beats `src/pkg/m.py`. CPython would pick the package directory over the
    module in the first case; kept the plan's rule.
  - Resolution details the plan left open: the longest-prefix fallback also applies to the module of a `from`
    import (`from a.b.missing import x` -> file of `a.b`); a submodule under a namespace package (directory
    without `__init__.py`) still resolves; a relative import may climb exactly to the repository root (base package
    = root, which covers repos whose root is itself a package) but never above it.

- Measured results (Windows laptop, Python 3.12, networkx 3.7, other sessions running at the same time):
  - 5,000-node random graph (15,000 random edges, 500 test nodes, largest SCC 3,803 nodes): `graph_features`
    8 to 12 s, almost all of it sampled betweenness (500 sources). Acceptance limit is 20 s.
  - 5,000-node random DAG (same sizes, no cycles): about 2 s.
  - SCC sizes plus transitive dependents (condensation + bitsets): 0.02 s (random) and 0.09 s (DAG) at 5,000 nodes.
  - Exact betweenness just below the sampling threshold (1,500 non-test nodes, 6,000 edges): 6.5 s cyclic, 1.5 s DAG.
  - Line coverage of `tdp_core.graph`: 100% (64 tests in `tests/graph`).
- Known issues / limitations:
  - Static resolution only: `importlib`/`__import__` calls, `sys.path` edits and script-directory imports
    (`scripts/run.py` doing `import util` for `scripts/util.py`) are not resolved.
  - `import a.b.c` adds one edge to the deepest existing module; the implicit imports of `a/__init__.py` and
    `a/b/__init__.py` are not added. Re-exports point at the `__init__.py`, which itself links to the defining module,
    so transitive dependents still flow through.
  - Transitive dependents use one bitset per SCC: memory about `n^2 / 8` bytes in the worst case (3 MB at 5,000
    files, 50 MB at 20,000).
  - Betweenness dominates runtime; exact up to 2,000 non-test files, so a strongly cyclic repo just under the
    threshold can take several seconds.
  - Under coverage tracing the 5,000-node random case takes about 22 s, so the perf test skips only its timing
    assertion when a tracer (coverage or debugger) is active; correctness assertions still run. CI runs pytest
    without coverage.
