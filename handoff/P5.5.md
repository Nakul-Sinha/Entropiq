## Behaviour

- `validate_repo_url`: strips surrounding whitespace; at most 2048 characters of visible ASCII; scheme `https` (any
  case) followed by `://`; no `@` anywhere before the path; port absent or exactly `443`; host `[A-Za-z0-9.-]+`,
  lower-cased, must equal an allowlist entry exactly (entries are stripped and lower-cased, empty ones dropped; a
  `str` allowlist raises `TypeError`); no query or fragment (even an empty `?` or `#`); path exactly `/owner/name`
  with an optional `.git` (any case, stripped once) and an optional trailing slash; each part `[A-Za-z0-9_.-]{1,100}`
  and not made only of dots; a name still ending in `.git` after stripping is rejected, so `clone_url` and
  `canonical_url` validate again to the same `RepoRef`. On github.com owner and name are lower-cased. The result is
  rebuilt from the checked parts: `canonical_url = https://<host>/<owner>/<name>`, `clone_url = canonical_url + ".git"`.
  With `resolve_dns=True`, after every other check, `socket.getaddrinfo(host, 443, type=SOCK_STREAM)` must return at
  least one address and every address must pass `is_public_address` (a mixed answer fails).
- `is_public_address`: requires `ip.is_global` and none of private, loopback, link-local, multicast, reserved or
  unspecified. IPv4-mapped and NAT64 `64:ff9b::/96` addresses are judged by the embedded IPv4 address; 6to4 with a
  non-public embedded IPv4 address and deprecated site-local `fec0::/10` are not public; non-IP strings are `False`.
- `validate_ref`: 1 to 255 characters of `[A-Za-z0-9._/-]` following git's ref rules (no leading `-`, `/` or `.`; no
  trailing `/`, `.` or `.lock`; no `..`, `//`, `/.` or `.lock/`); full refs only `refs/heads/...` or `refs/tags/...`;
  `HEAD` and hex shas pass as names.
- `check_repo_size`: other hosts return -1 with no request. github.com makes one `GET /repos/{owner}/{name}` (no
  retries, 10 s default timeout), sends `Authorization: Bearer` only for a non-empty token, and goes through
  `github_issues.urllib_transport` (same-host redirects only, so renamed repositories resolve and the token never
  leaves api.github.com). 404, 410, 451 and private or internal repositories raise `RepoNotFoundError` with one
  message. Rate limits (429, or 403 with `x-ratelimit-remaining: 0` or "rate limit" in the body), any other status,
  network errors and bodies without a valid non-negative integer `size` raise `RepoCheckUnavailableError` (fail
  closed). `size == max_kb` passes; a negative `max_kb` raises `ValueError` before any request.
- `check_mirror_size`: `size + size-pack + size-garbage` from `git count-objects -v` (KiB) through `run_git` with
  `--git-dir`. A relative `repo_dir` is made absolute against the current directory first (git runs inside
  `repo_dir`). `size == max_kb` passes; a missing or non-repository directory raises `GitError`.

## Deviations from the plan and why

1. `RepoRef` also has `slots=True` (same fields, same order, still frozen).
2. On github.com owner and name are lower-cased, so one repository always gives one `canonical_url` (the
   `repositories.url` unique key) and one mirror path. Other hosts keep case (GitLab paths can differ by case).
3. "Not `.` or `..`" was widened to "not made only of dots" (`...` is also refused).
4. Exactly one `.git` suffix is removed and `requests.git.git` is rejected, which makes validation idempotent.
5. Extra rejections: control, space and non-ASCII characters, `%`-escapes, empty or zero-padded ports, hosts with a
   trailing dot, IP literals (unless allowlisted, and then still DNS-checked), URLs over 2048 characters.
6. "Public" means `ip.is_global` plus the plan's list, so CGNAT `100.64.0.0/10`, documentation and benchmarking
   ranges also fail; mapped, NAT64 and 6to4 addresses are judged by their embedded IPv4 address.
7. `HostLookupError` subclasses `UnsafeRepoError`, so one except clause still catches everything, but an API can
   map it to 503 first.
8. `check_repo_size` has keyword-only `transport` and `timeout` (for offline tests) and reuses P2.5's
   `HttpResponse`, `Transport` and `urllib_transport` (public API, same-host redirects) instead of a second HTTP client.
9. Private and internal repositories are refused like missing ones, so the platform token can never be used to
   analyse private code and the API never confirms that a private repository exists.
10. When the size cannot be established the check raises `RepoCheckUnavailableError` (a `RuntimeError`, not an
    `UnsafeRepoError`) instead of letting an unbounded clone through.
11. Added `check_mirror_size`, so hosts without a size API are still bounded after cloning. It makes relative paths
    absolute, because git runs inside `repo_dir`.
12. Added `validate_ref` for the user-supplied ref of `POST /analyses`; it is stricter than P1.1's `check_rev`.
13. The hardening tests go beyond the plan: repository-local config cannot override the pinned `-c` options; http,
    ssh, scp-like, git, ext, fd, `file://` and local-path clones are refused even under a hostile global config that
    allows every protocol; hooks committed in the tree and live hooks installed through `GIT_TEMPLATE_DIR` never run
    during clone, fetch, `mine_history`, `list_files`, `read_blobs` or `update-ref`; `core.fsmonitor` from repository
    config never runs. Every planted-script test also runs plain git as a control that does trigger the script.
14. `tests/security/conftest.py` has an autouse fixture that fails any offline test that would resolve a real host
    (tests marked `network` are exempt).

## Known issues / limitations

1. The DNS check is a point-in-time check: git resolves the host again when it clones (a DNS rebinding window). The
   default hosts are trusted platforms; the worker can validate again right before fetching.
2. git follows HTTP redirects on the initial request (`http.followRedirects=initial`), so an allowlisted self-hosted
   server could redirect a clone elsewhere. `-c http.followRedirects=false` would close this but breaks renamed
   GitHub repositories, so it is not set.
3. Only `/owner/name` paths are accepted: GitLab subgroups (`group/sub/project`) are rejected.
4. The pre-clone size check exists only for github.com. Other hosts are measured after cloning with
   `check_mirror_size`, and the clone itself is bounded only by `run_git`'s timeout.
5. `check_mirror_size` bounds the packed size. A highly compressible blob can expand far more when read, and
   `read_blobs` has no per-blob cap. Analysis code should skip blobs larger than `settings.max_file_bytes` before
   reading them (`git cat-file --batch-check` or `git ls-tree -l` gives sizes).
6. Bug in `tdp_core/mining/mirror.py` (P1.5's file, not changed here, reproduced): `ensure_mirror` with a relative
   `dest` clones into `dest.parent/dest` (for example `m/m/x.git`) and then raises `GitError`, because git runs with
   `cwd=dest.parent` and the update and config calls run inside `dest`. Proposed one-line fix for its owner:
   `dest = dest.absolute()` at the top of `ensure_mirror`. Until then callers must pass absolute paths.
7. Without a token the GitHub API allows 60 requests per hour per IP address; pass `GITHUB_TOKEN`.
8. Windows-only path quirks (reserved names such as `con` or `nul`, trailing dots) can affect mirror paths built from owner and
   name; production runs on Linux.
9. `validate_ref` refuses some legal git names (non-ASCII, `+`, `@`) by design.

## Notes for dependent steps (by ID)

- P5.4: order in `POST /analyses`: `ref = validate_repo_url(body.repo_url, settings.allowed_git_hosts)`;
  `validate_ref(body.ref)` when a ref is given; `check_repo_size(ref, token, settings.max_repo_kb)` (gives a clean
  not-found for missing or private repositories before git runs), where `token` is a plain `str` or `None`:
  `settings.github_token` is a `SecretStr`, so pass `settings.github_token.get_secret_value()` when it is set (a
  `SecretStr` itself would be sent as `Bearer **********`, and every check would then fail with HTTP 401); then
  `run_git(["ls-remote", "--", ref.clone_url, <patterns>], <neutral cwd>, timeout=5)`. For a branch or tag ask for
  `refs/heads/<ref>`, `refs/tags/<ref>` and `refs/tags/<ref>^{}` explicitly (a bare pattern matches any ref tail),
  prefer the branch, and use the peeled `^{}` sha for annotated tags; an empty answer means not found. Store
  `ref.canonical_url` as `repositories.url` with `ref.host`, `ref.owner` and `ref.name` (`RepositoryRepo.get_or_create`,
  `AnalysisRepo.find`). Catch order: `HostLookupError` and `RepoCheckUnavailableError` give 503, `RepoTooLargeError`
  gives 413 or 422, `RepoNotFoundError` gives 404 or 422, any other `UnsafeRepoError` gives 422; `TransientGitError`
  gives 503 and `GitError` gives 422. All messages are safe for an RFC 9457 `detail`. These calls block (DNS, HTTP,
  git), so call them through `run_in_threadpool` or `asyncio.to_thread` from async handlers. Import
  `UnsafeRepoError` and `RepoRef` from `tdp_core.security.urls` (`limits` does not re-export them, and mypy strict
  rejects implicit re-exports).
- P5.3: mirror path `settings.repo_cache_dir.resolve() / ref.host / ref.owner / f"{ref.name}.git"` (it must be
  absolute, see known issue 6; `.env.example` uses a relative `./data/mirrors`); `ensure_mirror(ref.clone_url, dest)`
  without `allow_file_protocol` in production; then `check_mirror_size(dest, settings.max_repo_kb)`, and on
  `RepoTooLargeError` remove the mirror and fail the analysis with `str(exc)`. Optionally call
  `validate_repo_url(url, hosts)` again right before fetching. The exceptions rebuild from their args, so they are
  safe to pass through Celery.
- P7.1: `validate_repo_url(url, DEFAULT_ALLOWED_HOSTS)`, then `ensure_mirror(ref.clone_url, <absolute temp dir>/repo.git)`;
  `validate_ref` for `--ref`.
