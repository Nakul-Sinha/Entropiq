- Deviations from the plan and why:
  - P2.3 is not merged, so no `SatdClassifier` Protocol is defined here (none is needed: `JsonSatdClassifier`
    matches `predict_proba(self, texts: Sequence[str]) -> np.ndarray` structurally). The core test declares a
    local Protocol of the same shape and mypy checks the default classifier against it.
  - The JSON stores `terms` as a list in column order (position = index) instead of a term-to-index object, and
    rounds `idf` and `coef` to 9 decimals, to keep the file small. `from_json` rebuilds the mapping. Measured error
    from rounding: 1.05e-10 against the 1e-6 tolerance.
  - Added `max_features=40_000` (the most frequent n-grams after `min_df=2`), applied identically in every LOPO
    fold and in the final fit. Uncapped, the vocabulary is 57,389 n-grams and the file 2,287,285 bytes, which is
    over the repository's `check-added-large-files --maxkb=2048` hook. The cap costs 0.010 macro F1 (see below).
  - `predict_proba` returns 1-D P(debt) (the P2.3 Protocol), not scikit-learn's `(n, 2)` array.
  - `from_sklearn` lives in the core module (duck-typed, no scikit-learn import) so the format has a single reader
    and writer and the core tests need nothing from `tdp_ml`. It refuses settings the runtime does not reproduce
    (custom token pattern or analyser, stop words, accent stripping, preprocessor, `binary`, `use_idf=False`,
    norms other than l2, non-float64 output) and class labels other than `[False, True]` / `[0, 1]`.
  - Download pinned to the dataset commit and verified by git blob SHA-1 (zip and CSV SHA-256 are recorded too).
    Debt = any classification other than `WITHOUT_CLASSIFICATION`. Duplicated comments (23,459 rows repeat an
    earlier text) and comment markers (`//`, `/*`) are kept, as in the literature; the tokenizer drops punctuation.
  - The model metadata names the pinned dataset only when the CSV's SHA-256 matches it; a custom CSV is recorded
    as `custom CSV <name>` with no URL (so a fallback model can never claim the wrong provenance).
  - Added the `tdp-ml satd` plug-in and `ml/tests/satd/` (section 15.4 and the testing rules). No MLflow run:
    the plan does not ask for one; the JSON report and this handoff hold the numbers. Threads are capped with
    `threadpoolctl`. lbfgs with no `penalty` argument (deprecated in scikit-learn 1.9; L2 is the default).
  - No new dependencies, no `pyproject.toml` or `uv.lock` change.

- Known issues / limitations:
  - Domain shift: trained on Java comments from 10 older open-source projects, applied to Python comments. Some
    strong terms are project artefacts (for example "dms", "author", "notused").
  - The original labels call some keyword comments not debt (for example localisation TODOs: "todo localize",
    "todo charset", i18n). The model learns that, so it filters a few keyword comments that a reader would call
    debt. A label-corrected version exists (Yu et al., Jitterbug, github.com/ai-se/tech-debt, `new_data/corrected`,
    426 relabelled comments); it was not used, to stay comparable with the literature. A possible later improvement.
  - The keyword rule alone scores higher F1 than the classifier on this dataset, also inside the candidate subset
    (0.922 vs 0.913). The classifier is more precise (0.869 vs 0.855) at some recall cost. Whether it helps the
    ranker is an empirical question for the ablation (P3.6): compare `satd_model=None` with the classifier.
  - C was selected on the same LOPO folds that report the F1, so 0.662 is slightly optimistic (the three C values
    differ by 0.02 to 0.11).
  - The 40,000-term cap trades 0.010 macro F1 for a file under 2 MB.
- Notes for dependent steps (by ID):
  - P2.3: `satd_features(..., classifier)` can take `load_default_classifier()`. `predict_proba(texts)` returns a
    1-D float64 array of P(debt) in the order given, accepts `[]`, and the model was trained with balanced class
    weights, so 0.5 is the balanced decision point. Texts are free text (no `#` needed; punctuation is ignored).
  - P2.7: pass `satd_model=load_default_classifier()` (or `None` for keyword-only counting). It loads once per
    process (about 30 ms), is immutable and thread-safe, and pickles for process pools (it rebuilds itself on
    unpickling). It was trained on whole Java comment blocks, so single lines work; joining adjacent comment lines
    into one text is an option.
  - P2.8 / P5.2: use the same loader. Q features depend on these weights, so retraining the JSON means rebuilding the
    dataset. Record `load_default_classifier().source_sha256` (P3.0 / P3.7 bundle metadata) to tie features to the
    exact weights.
  - P3.6: the keyword baseline above is the natural ablation partner for the classifier.
  - P7.4: the JSON ships inside the `tdp_core` wheel (checked with `uv build --package tdp-core --wheel`).
  - P8.3: cite the dataset (citation above, also in the model metadata `license` field).
