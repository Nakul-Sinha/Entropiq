- Deviations from the plan and why:
  - D1. Commands are a plug-in module (15.4), not `cli.py`.
  - D2. One MLflow run per invocation and protocol. Tuning happens only when `--params` is absent: the real procedure tuned once in the temporal run and reused `ranker_params.json` for LOPO and both monotone runs ("tuned once on temporal folds").
  - D3. 50 trials (15.6 allows 50 when a trial takes under a minute; measured 0.6 to 1.2 s per trial on the GPU).
  - D4. Forward folds as planned (two folds: 20 and 40 training queries). `n_estimators = max(1, floor(1.1 * mean(best_iteration + 1) + 0.5))`. Early stopping uses the validation fold that is scored, which is standard and slightly optimistic for the tuning value.
  - D5. Queries whose grades are all 0 are dropped from every training set and tuning validation set (none exist in the real data); test queries are never filtered.
  - D6. The out-of-fold scores are the LOPO cross-fit over all rows (each repository scored by the model that never saw it, every snapshot), not forward-fold predictions: they cover every row with the production score scale and need no extra fits.
  - D7. The LOPO run also trains `model/ranker.json` on all 27,208 rows with the same params (the production candidate, because the temporal model leaves out the 3 newest snapshots per repository). The temporal run logs `model/ranker_temporal.json`.
  - D8. The comparison uses P3.2's `baselines_<protocol>.parquet` when every model covers the ranker's qids and its provenance note names the same dataset sha256 (P3.2's recommendation); otherwise the identical internal hotspot. P3.2 code is not imported.
  - D9. MLflow 3 needs `MLFLOW_ALLOW_FILE_STORE=true` for file stores; `configure_mlflow` sets it (and turns telemetry and the agent hint off) before importing mlflow. Copied file stores keep absolute artifact paths, so `tdp-ml mlflow-relocate` rewrites `meta.yaml` files.
  - D10. Scores go through `tdp_core.model.ranker.Ranker`, so stored scores equal bundle scores; boosters are switched to CPU after fitting (no device mismatch warning).
  - D11. `--device auto` falls back to CPU; an explicit `cuda` fails loudly. GPU and CPU results can differ slightly with subsampling; the run records the device.
  - D12. `min_child_weight` is searched as a float.
  - D13. `code_git_sha` comes from `TDP_CODE_SHA` on the box (the archive copy has no `.git`).
  - D14. With `--no-tracking` no booster is kept; boosters live only in MLflow artifacts.
  - D15. Additions to the planned API: `train(..., params_path=...)` records a loaded params file in `files["params"]`; `TrainOutcome.others` holds the comparison runs; `p_greater` computes the one-sided gate; `comparison_runs(..., dataset_sha256=...)`. MLflow also gets `<protocol>_ndcg_10_diff_<model>` for every comparison model.

- Known issues / limitations:
  - The ranker does not beat the hotspot heuristic significantly: temporal NDCG@10 is 0.015 higher (p 0.205) and LOPO 0.005 lower (p 0.507), and Popt is lower under both protocols. With 20 test queries the intervals are wide. The P3.7 gate (one-sided p < 0.05 vs hotspot) fails with these numbers.
  - The tuned model is small (depth 3, 145 rounds at learning rate 0.02); tuning folds hold only 20 and 40 training queries, so the chosen round count is conservative for the 160-query production model.
  - The tuning value (0.687) uses the same fold for early stopping and scoring (slightly optimistic).
  - GPU and CPU fits can differ slightly with subsampling; the reported numbers are from cuda.
  - `/work/code-P3.3` is left on the box for reproduction; no jobs are running there.
