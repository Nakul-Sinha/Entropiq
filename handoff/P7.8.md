## What was built

Six interactive commands of the Entropiq shell, each also a non-interactive `tdp` subcommand, all plug-ins of
the P7.1 registry (no shared CLI file changed):

| Shell | Subcommand | Group | Shows |
|---|---|---|---|
| `/files [--band B] [--type T] [--path PREFIX] [--sort priority\|risk\|cost] [--top N]` | `tdp files` | Explore | ranked table (rank, path, priority and band, risk, cost range, debt types, top reason), paged in the shell |
| `/file <path or rank>` | `tdp file FILE [TARGET]` | Explore | detail screen: header panel, reasons and mitigations, SHAP bars per family, most complex functions, connections, 24-month sparkline, debt remedies, cost breakdown |
| `/graph [PATH or RANK] [--depth N] [--top N]` | `tdp graph [--file F]` | Explore | central files (transitive dependents, PageRank), import cycles, hidden couplings; with a file, a tree of its importers and imports |
| `/tree [FOLDER] [--depth N] [--files]` | `tdp tree [--path F]` | Explore | folder hierarchy with file count, lines of code and highest band per folder, coloured by band |
| `/diff --base REV [--top N]` | `tdp diff --base REV` | Report | ranked files changed in `REV...HEAD` with a Change column, band summary, unranked changes |
| `/trend` | `tdp trend [TARGET]` | Analysis | saved analyses of the repository with Critical count and hours, two sparklines, change since the previous one |

The `/files` pager opens a `files ❯` sub-prompt: `n` next page, `p` previous, a rank opens that file's detail,
Enter or `q` goes back, a `/command` leaves the pager and runs (so `/quit` closes the shell).

## JSON documents (all stable)

Every view document starts with `json_header`: `schema`, `repo`, `sha`, `model_version`, `demo_model` (trend has `schema`, `repo`, `slug` instead).
- `entropiq.files.v1`: `query` {band, type, path, sort, top}, `total` (rows matching), `files` (analysis rows).
- `entropiq.file.v1`: `rank`, `files`, `file` (FileScore), `extra` (FileExtra or null), `plan_step`, `remedies`.
- `entropiq.graph.v1`: `summary` {files, import_edges, cycles, hidden_couplings}, `central` [{rank, path, priority, band, dependents, importers, imports, pagerank}], `cycles` [{size, files}], `hidden_couplings` [{source, target, confidence}] (lists cut at `--top`, 0 = all).
- `entropiq.graph.file.v1`: `file` {rank, path, priority, band}, `dependents`, `dependencies` (direct, rank order), `all_dependents`, `all_dependencies` (transitive, path order), `test_importers`, `cycle`, `hidden_couplings` [{path, confidence}].
- `entropiq.tree.v1`: `root` folder node {name, path, files, sloc, priority, band, top_file, collapsed, children}; file nodes {name, path, rank, sloc, priority, band} only with `--files`.
- `entropiq.diff.v1`: `base`, `base_sha`, `merge_base`, `head_sha`, `summary` {changed, ranked, critical, high, medium, low}, `files` (analysis rows plus `change`, `old_path`), `unranked` [{path, change, old_path}].
- `entropiq.trend.v1`: `order` (`commit_time` or `analysis_time`), `points` [{number, sha, committed_at, analyzed_at, model_version, demo_model, files, critical, high, medium, low, critical_hours}].

## Deviations from the plan and why

1. Interactive views act on the loaded analysis; `/diff` compares REV with the analysed commit (`loaded.result.sha`), so the priorities shown belong to the head of the range. `tdp diff` analyses `--ref` (default HEAD) first, which matches the plan's `REV...HEAD`.
2. Every subcommand has `--format table|json` (diff also `md`) for scripting and the Action.
3. Ranks are global priority ranks everywhere (`#` column, `/file N`, pager numbers), whatever filter or sort a table uses.
4. The `/files` pager always opens its sub-prompt, even for one page, so a rank opens a file.
5. `/tree` shows folders by default; `--files` adds file leaves with rank. Lines of code are summed over ranked files only.
6. Graph views use ranked non-test files only, like `GraphData`; test importers are listed separately; cycles are the strongly connected components of the stored import edges.
7. `/trend` orders saved analyses by commit date (one `git rev-list --no-walk=unsorted --timestamp` call), falling back to analysis time when the repository is unavailable; a notice flags mixed models. `tdp trend` only reads the local cache (no analysis, no network, no `--dev-model`).
8. One edit to a P7.1 test file (the `file` to `probe` rename above).
9. New fixtures live in `cli/tests/views/conftest.py` (the linked RepoBuilder repository) instead of the P7.1 conftest.
10. Groups: files, file, graph and tree in Explore, diff in Report, trend in Analysis next to `/history`. No aliases, to avoid clashes with the parallel views (plan, what-if, advice).
11. `/files --path` is a plain prefix (`app/api` also matches `app/apiary.py`); `/tree FOLDER` matches whole path components.

## Measured results

- psf/requests mirror (22 ranked files): first `tdp files` 13 s (analysis included); later subcommands reuse the saved analysis and take about 3 s each; the piped shell session above (analysis reused) 5 s. `tdp graph` finds 74 import edges and one 8-file cycle; `tdp diff --base HEAD~30` lists 23 changed files, 10 ranked.

## Known issues / limitations

1. At 80 columns the ranked table squeezes the Debt and Top reason columns (same as the `tdp analyze` table of P7.1); 120 columns or more read well.
2. The pager's prompt_toolkit sub-prompt runs only on a real terminal and is not covered by tests (plain-line input is).
3. `/trend` relies on saved analyses; analyses made with different models are flagged but still listed together.
4. `tdp trend` prints the demo-model notice on stderr like `entropiq history` (P7.1 known issue 5).
