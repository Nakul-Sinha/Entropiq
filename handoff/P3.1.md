  `results/<prefix>_<protocol>.parquet` (for example `baselines_lopo.parquet`, `ranker_temporal.parquet`).

- Deviations from the plan and why:
  1. **Two extra modules.** `harness.py` runs a model under a protocol, so baselines, the ranker and ablations
     share identical splits and output, which the paired tests need (pairing is by qid). `synthetic.py` gives
     P3.2, P3.3 and P3.6 one deterministic dataset in the real layout to develop and test on.
  2. **Labels are hidden from the model.** `run_protocol` calls `fit_predict(train, test)` with the test rows
     minus `LABEL_COLUMNS` (`latent_defects`, `future_churn`, `pain`, `grade`, `has_latent_defect`), so a scorer
     cannot read the answers by accident. Training rows keep every column. `qid` stays in both. A score Series is
     aligned to the test rows by label (any order); any other array-like is taken in test-row order.
  3. **Metric names.** Columns are identifiers (`ndcg_10`, `precision_10`, `recall_20loc`, ...); display names
     live in `METRIC_LABELS`. NDCG@5 and NDCG@20 were added because they cost nothing.
  4. **NaN policy.** NDCG when every grade is 0, Recall@20%LOC and Popt without defects (or Popt without SLOC),
     Spearman with fewer than 2 files or a constant input, AUC-PR without positives, and any empty input give
     NaN. Summaries and tests ignore NaN (NaN-aware means, NaN pairs dropped). Invalid input (NaN scores,
     negative counts, probabilities outside [0, 1], unequal lengths) raises `ValueError`; inside `evaluate`
     the message starts with `qid <q>: `.
  5. **k larger than the query.** NDCG@k and P@k use `min(k, n)` items, so small repositories are not
     penalised.
  6. **Recall@20%LOC and Popt** use `latent_defects` as the defect count and `sloc` as effort. The Recall prefix
     is inclusive with a 1e-9 relative tolerance and stops at the first file that does not fit (cumulative
     SLOC is non-decreasing). With zero total SLOC every file fits.
  7. **Popt** returns 1.0 when `A_opt - A_worst <= 1e-12` (all densities equal; a tolerance instead of an exact
     zero test), clips to [0, 1], and gives a defective file with 0 SLOC infinite density (first in the optimal
     order, last in the worst).
  8. **ECE** uses equal-width, left-closed bins; probability 1.0 falls in the last bin.
  9. **AUC-PR** is average precision computed in numpy (equal to `sklearn.metrics.average_precision_score`
     within 1e-12 on tie-heavy data). sklearn is not imported by the library because `sklearn.metrics` takes
     about 4 s to import here.
  10. **Bootstrap.** The estimate is the query-level mean; the 95% interval is the percentile interval of
      replicates that resample repositories with replacement (multinomial weights, so each replicate is a
      query-weighted mean of the drawn repositories). Every `(model, protocol)` group uses the same seed and
      therefore the same draws, which keeps the intervals of two models on the same repositories comparable.
  11. **Wilcoxon** pairs on qid (inner join, NaN pairs dropped), is two-sided by default, drops zero
      differences (`zero_method="wilcox"`), and returns statistic 0 and p 1 when every difference is zero
      (scipy would warn). Holm runs across the baselines of one call, over the finite p-values only. The
      `a` frame and every baseline frame must hold one run each (duplicate qids raise).
  12. **Splits.** The embargo is per repository: a training row at T needs `T + H <= V` for that repository's
      test or validation time V, plus `T < V` (it matters only for H = 0). Folds and LOPO splits with an empty
      training set are skipped with a warning; `run_protocol` fails when no split is usable. Indexes returned are
      index labels in input order, so any unique index works (the tests use string indexes).
  13. **`evaluate`** requires an integer `qid`, sorts each query by path (ties in the score break by path
      ascending), selects only the columns it needs (the dataset has about 100), and rejects duplicate
      `(qid, path)` rows and a qid that spans several repositories, snapshot indexes or snapshot times.
  14. **No CLI command and no dependency change.** The harness is a library; commands come with P3.2 and P3.3.

- Measured results:
  - 116 eval tests, about 15 s locally (the slowest is the 200-example brute-force split check, about 4 s);
    line coverage of `tdp_ml.eval` is 100%. Full suite after rebasing on main: 1079 passed.
  - `make_synthetic_dataset(10, 10, 200)` (20,000 rows) builds in 0.2 s; `evaluate` on its 100 queries takes
    about 0.06 s.
  - Synthetic signal (10 repos x 10 snapshots x 200 files, all queries, mean NDCG@10 / P@10 / Recall@20%LOC /
    Popt / Spearman): hotspot 0.549 / 0.565 / 0.234 / 0.540 / 0.472; prior_latent_bugs 0.455 / 0.449 / 0.336 /
    0.618 / 0.273; cc_sum 0.438 / 0.431 / 0.147 / 0.439 / 0.368; sloc 0.314 / 0.317 / 0.091 / 0.349 / 0.241;
    random 0.182 / 0.156 / 0.204 / 0.497 / 0.008. Grade shares 0..4: 0.286, 0.356, 0.213, 0.107, 0.038.
  - Acceptance one-liner (default synthetic data, LOPO, 4 repos): hotspot NDCG@10 0.604 [0.382, 0.825].
- Known issues / limitations:
  - With few repositories the bootstrap interval is coarse (4 repositories give at most 35 distinct draws).
  - The synthetic data has the right columns, dtypes and qualitative signal, not realistic feature
    distributions; do not tune hyperparameters on it.
  - Library code passes `mypy --strict`, but CI only type-checks `packages/core`; run the strict command above
    after changing `tdp_ml.eval`.
- Notes for dependent steps (by ID):
  - **P3.2 (baselines):** call `run_protocol(df, protocol, fit_predict, model=<name>)` once per baseline and
    protocol, concatenate the `per_query` frames and write them with
    `save_per_query(frame, per_query_path("baselines", protocol))`; summarise with `summarize` and
    `summary_markdown`. For `random`, average the per-query metrics of 100 seeded runs per qid (keep the
    `model`, `protocol`, `split` and query columns). The test frame given to `fit_predict` has no label columns,
    so `rf` and `xgb_point` fit on the training frame only. Develop on `make_synthetic_dataset(n_repos=6,
    n_files=80)` or similar.
  - **P3.3 (ranker):** `train_idx, _ = temporal_split(df, H)`, then `forward_folds(df.loc[train_idx], H, n_folds=2)`.
    Objective: mean over folds of `evaluate(valid.assign(score=pred), "score")["ndcg_10"].mean()`; queries with
    all-zero grades give NaN and are skipped by the NaN-aware mean. Final numbers come from `run_protocol` and go
    to `per_query_path("ranker", protocol)`; `ProtocolRun.scores` holds the test scores (OOF scores for P3.4
    still come from your own fold loop). Embargo consequence: with step 182 and H 365 the two snapshots before a
    test or validation snapshot are dropped. With 8 snapshots per repository the temporal train keeps 5, fold 0
    trains on 1 snapshot per repository and fold 1 on 2. `XGBRanker` needs rows grouped by qid: sort the frames
    by `qid` before fitting.
  - **P3.4 (calibration):** `brier`, `ece(prob, y, bins=10)` and `reliability_table` (for the diagram) on the
    pooled temporal test rows; `evaluate(df, score_col, prob_col=...)` adds per-query `brier`, `ece`, `auc_pr`.
  - **P3.6 (experiments):** `wilcoxon_holm(model_pq, {name: baseline_pq, ...}, metric)` per metric (Holm across
    baselines) and `cliffs_delta`; `effort_curve(scores, sloc, latent_defects)` for the lift chart (pass
    `defect_density(sloc, latent_defects)` as scores for the optimal curve; a plain `latent_defects / sloc`
    gives NaN for empty files such as a bare `__init__.py`, which the parser does not skip, and
    `effort_curve` rejects NaN scores); `summary_markdown` and `comparison_markdown` for
    `results/report.md`. Filter each frame to one model and protocol before testing.
  - **P3.7 (promotion gates):** the `summarize` interval on LOPO `ndcg_10`;
    `wilcoxon_holm(cand, {"hotspot": hot}, "ndcg_10", alternative="greater")` with `p_value < 0.05`;
    `ece <= 0.05`.
  - Temporal and LOPO test the same queries (each repository's last snapshot), so their qids line up and the
    per-query frames of both protocols can be compared directly.
