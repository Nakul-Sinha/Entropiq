- Shared definitions (module docstring):
  - T is `snapshot.time`; a naive time raises `ValueError`. `snapshot.sha`, `repo`, `index` are not used.
  - History up to T: `author_time <= T` when `reachable is None`, otherwise exactly the commits whose sha is in `reachable` (section 15.5), with no time filter; unknown shas are ignored.
  - Counted commits: history commits with `is_bulk == False`, taken from the mined column (`settings.bulk_commit_files` is not applied again).
  - Touching: names of `p` = `lineage.get(p, frozenset()) | {p}`; a commit touches `p` when a change row has `path` or `old_path` among them; once per file, churn = sum of `added + deleted` over the matching rows (a rename row matching twice counts once).
  - Age in days = `max(T - author_time, 0) / 86400`; decay weight `2 ** (-age / half_life_days)` (equal to the plan's `exp(-ln2 / half_life * age)`, exactly 0.5 at one half-life).
  - Implementation: integer codes with `pyarrow.compute.index_in`, `np.unique`, `np.bincount` and `ufunc.at`. The only Python loops are over requested paths and their lineage names (and paths x months for the activity tuples).
- Deviations from the plan and why:
  1. **Files without counted touching commits are not "new".** The plan gives them zeros and `is_new = 1`, but a file that exists at T was created at or before T. Instead: `age_days` uses every touching commit **including bulk ones** (a bulk commit touching the file proves it existed); a file with no touching commit at all gets the observed history span (T minus the earliest history commit, bulk included, clipped at 0; 0.0 without history), a lower bound on its true age; `staleness_days` falls back to `age_days` when there is no counted touch. Counts, churn, decay, burstiness, ownership and activity stay non-bulk; `owner_active` stays 0 for such files. Measured on the shared mirrors at the last training snapshot, mining the last 3 years (what inference does) leaves 10 of 36 `.py` files (psf/requests), 15 of 61 (pallets/click), 170 of 409 (celery) and 12 of 83 (paramiko) without a counted touch, so the plan's rule would call 14 to 42 percent of real files brand new with zero age and staleness. With full history only bulk-only files are affected (celery 6, the others 0).
  2. Paths are sorted and de-duplicated in every output; lineage lookups always include the path itself.
  3. The 90 and 180 day windows come from `settings.recent_days` (default `(90, 180)`); both bounds are inclusive.
  4. `burstiness` is the population coefficient of variation (ddof 0) of gaps between consecutive counted commits, using author times clipped at T (ties ordered by sha); 0.0 with fewer than 3 commits or a zero mean gap.
  5. Owner tie-break: most counted commits, then the author whose latest touching commit to this file is most recent, then the smaller email. `owner_active` looks at the owner's latest **non-bulk** commit anywhere in the history up to T; the window `<= owner_active_days` is inclusive.
  6. `commit_activity` counts non-bulk commits per UTC calendar month; the window ends with T's month; a reachable commit authored after T counts in T's month.
  7. Additions: the public helper `file_touches` (so prior bug-fix counts can reuse the exact matching rule) and the three column constants.
  8. Validation: `ValueError` for a naive T (all four functions), `half_life_days <= 0` (`evolution_features`) and `months < 1` (`commit_activity`).
  9. Kept as planned: matching on `path` OR `old_path`. It is harmless when lineage is consistent; the name-reuse inflation comes from the lineage being a set of names (P1.1 limitation) and dropping `old_path` would not fix it.

- Known issues / limitations:
  - **Train/serve skew**: training mines full history, inference mines `history_window_days` (3 years). Age, counts, churn, authors and the owner are truncated at inference (numbers above). Options: mine full history at inference (one `git log` of psf/requests takes about 1.4 to 2 s, celery about 9 s), or apply the same window when building training features.
  - Lineage is a set of names (P1.1): a recreated file or a shim that reuses an old name inherits the old file's history.
  - Author identity is the mailmapped, lowercased email only; one person with two emails counts as two authors.
  - `age_days` for an untouched file is a lower bound (history span); in a windowed history, a touched old file can get a smaller age than an untouched one.
